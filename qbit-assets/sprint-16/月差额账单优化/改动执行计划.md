# 月差额账单优化改动执行计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成月账单 0 费用项隐藏、毛利返现接入返现账单与差额计算、账单更新时间核验，并将毛利返现与 Active Card Details 以独立 CSV 文件加入对应 ZIP；同步处理差额通知链路。

**Architecture:** 保留现有 `api_client_bill`、`api_client_bill_statement`、`cash_back_bonuses` 和 `api_client_netting_bill` 的领域边界。先统一账单有效金额与返现汇总数据，再让 PDF/CSV/API 共用同一口径；差额服务只负责读取快照、计算差额和更新状态，不在 Controller 中增加业务逻辑。导出与通知分别复用现有返现导出服务和差额通知流程。

**Tech Stack:** Java 17、Spring Boot 3.0.2、MyBatis-Plus、PostgreSQL、JUnit/Mockito、现有 PDF/Excel/CSV 导出模板和通知模板。

**Export Format Decision:** 当前月账单和返现明细以 ZIP + CSV 为主，CSV 不支持 Sheet。毛利返现使用独立 `Infinity Card Revenue Sharing Rebate.csv`，Active Card Details 使用独立 `Infinity Card Active Card Details.csv`。PDF 中毛利返现独立展示；是否拆成独立 PDF 文件由产品最终确认。

## Global Constraints

- 遵循项目 `AGENTS.md`：Controller 不直接调用 Mapper，业务写入经过 Service，需要事务时使用 `@Transactional(rollbackFor = Exception.class)`。
- 金额统一使用 `BigDecimal`，金额比较使用 `compareTo()`，有效金额优先使用 `adjust_amount`。
- 返现项目沿用 `CashBackBonusProject` 已有的 QI/BZ RS 毛利返现枚举，不新增重复枚举。
- 不改变已有 API 路径；新增响应字段使用现有命名和时间戳序列化方式。
- 新业务规则必须覆盖成功、拒绝、金额相等、金额方向变化和重复触发场景。
- 每个任务完成源码检查、对应测试和 `git diff --check`；不跳过失败测试。
