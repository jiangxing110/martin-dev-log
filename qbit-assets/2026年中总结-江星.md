# 2026 年中工作总结

## 一、整体回顾

2026 年上半年，我主要围绕量子卡、账户体系、月结费用、数据看板、风控标签、公共服务通知等方向开展服务端研发工作。根据 Jira 记录，截至本次统计共完成并关闭 120 个事项，累计 Story Points 804，其中高优先级事项 37 个、中优先级事项 12 个，覆盖 PD、IN、OB、STAT、OP、ODD、CDD、SEC 等多个业务项目。

整体来看，今年上半年的工作特点是需求密度高、业务链路长、跨系统协作多。一方面要支撑业务快速迭代，例如量子卡费用调整、CaaS 月结账单、返现、渠道成本、客户毛利等需求；另一方面也要兼顾已有系统的稳定性、数据准确性和可维护性，例如历史数据清洗、统计口径统一、慢接口优化、账户清退流程重构、标签数据治理等工作。

在执行过程中，我持续保持对业务规则、数据口径和系统边界的关注，尽量在交付功能的同时，把后续可扩展性、问题排查效率和数据一致性一起考虑进去。

## 二、核心工作与成果

### 1. 数据看板与经营分析能力优化

今年上半年，我参与了多个数据统计和看板类需求，重点覆盖客户毛利、渠道成本、销售收入、量子卡收入成本、用户流失预警、月度明细、资金对账单等方向。

代表工作包括：

- 客户成本毛利总维度聚合及页面接口开发。
- 金融渠道成本按产品线均摊到客户每天。
- 新增量子 LS 渠道成本、金融渠道成本清洗。
- 创建客户维度聚合表、历史数据清洗。
- 客户量子卡渠道毛利统计、毛利总计后端逻辑、渠道毛利查询性能优化。
- 有效收入规则变更、新增 SL 卡段收入与成本。
- 月度明细数据优化、指标枚举补充、API 客户实收收入统计规则更新。
- 资金对账单大数据量导出异常排查与优化。

这些工作提升了经营数据的完整性和可用性，让业务侧能够从客户、渠道、产品线、卡段、收入成本等多个维度查看数据。对于统计类需求，我重点关注口径一致性和数据链路可追溯性，避免前后端、业务侧、数据侧对同一指标出现理解偏差。

在性能方面，针对数据量较大的查询和导出场景，我参与了聚合表设计、SQL 优化、并发查询超时控制等工作，减少慢查询对线上服务的影响，也提升了报表查询和导出体验。

### 2. 月结账单、费用与费率体系建设

费用和月结是上半年投入较多的方向之一，涉及 scheme fee、Fx/CB fee、settlement fee、活跃卡费、制卡费、IDV 费用、账户费率、默认月结费率、账单补扣等多个复杂场景。

代表工作包括：

- Scheme fee 月结、VRM 调价月结。
- Fx/CB fee 手续费计算逻辑调整。
- Settlement fee 计算公式调整，以及 BB 卡段 settlement fee 支持单笔费用。
- PC 卡段 API 月结默认费率、BB/BZ 卡段默认月结费率调整。
- 账户费率重构、量子卡账户费率调整、月结账单账户费率调整。
- CaaS 月结账单 IDV 费用、活跃卡费补扣及账单金额取值优化。
- 新增实体卡陶瓷费用项、制卡费调整、资金对账单增加 system_fee。
- 返现记录、月结账单记录、毛利返现计算、BZ 净消费额返现等相关后端开发。

这部分需求的特点是规则细、影响面广，并且直接关联客户收费和财务数据。我在开发过程中重点校验费用来源、计算公式、账单展示、补扣逻辑和历史数据兼容性，尽量减少因口径不清或边界条件遗漏导致的账单偏差。

通过这些迭代，系统对不同卡段、不同客户类型、不同费用项的支持更加精细，也为后续 API 客户、CaaS 客户、渠道客户的收费模式扩展打下了基础。

### 3. 账户、客户与渠道体系迭代

账户和客户体系是今年上半年的另一条主线，涉及量子账户、API 客户、渠道方、Distributor、Gateway、白标 Admin、KYC/KYB、ODD 年审、账户清退等多个业务场景。

代表工作包括：

- 量子账户、预算和储值卡相关服务端开发。
- ODD 账户年审、ODD 邮件优化、账户休眠规则调整。
- 账户相关清退流程实现及前置技术改造总结。
- 创建 API 客户节点解耦、API 客户模式校验前置账户结构改造。
- Gateway/Distributor 商户提交 KYC/KYB 优化、B2B2B 模式入口和合规后台审批。
- Admin 新用户全量信息、用户资金冻结管理、月度对账单支持按母账户 ID 模糊搜索子账户。
- 子账户展示名单筛查详情、合规提交页面改造、公司业务信息模块补充。
- 渠道方新增国内/海外归属、大客户管理部配置、销售推荐码统计到 master/sub 层。
- Infinity Launch 钱包余额优化、白标 Admin 重置 Sumsub、客户打标等需求。

这些需求提升了账户链路在不同客户类型、不同组织层级下的适配能力，也让 Admin、Gateway、Distributor 等后台系统在客户管理、合规审批、账户查询和信息展示上更贴近业务使用场景。

在实现过程中，我更关注账户结构变更对旧逻辑的影响，尤其是 master/sub、API 客户、渠道方客户、白标客户等多层关系下的数据查询和权限判断，避免局部改动影响存量客户流程。

### 4. 风控、标签与安全能力建设

上半年我也参与了标签库、自动化打标、退款延迟清算标签、账户休眠、安全漏洞修复、短信轰炸应急排查等工作。

代表工作包括：

- 后端标签库建立及标签数据清洗。
- 自动化打标开发。
- Admin 标签管理优化。
- 退款延迟清算标签及导出。
- 未提交 KYC 客户不走 ODD 180 天未登录账户自动休眠逻辑。
- 海外版账户休眠定时器暂停。
- 白标密码修改未校验旧密码安全漏洞修复。
- 短信轰炸限制绕过应急排查。

这部分工作让标签能力从单点功能逐步向可配置、可治理、可复用的方向推进，也提升了风险识别、客户分层、异常账户处理和合规管控的效率。

对于安全和风控类问题，我在处理时更强调及时响应和闭环验证。对线上风险、绕过场景和权限校验问题，会优先定位影响范围，再完成修复、验证和相关数据处理，保证问题不会停留在表面修补。

### 5. 公共服务、通知与后台体验优化

除核心业务模块外，上半年还完成了多项通知、邮件、后台体验和接口优化工作。

代表工作包括：

- Interlace 英文自动邮件新增。
- 名单筛查补充合规材料邮件文案优化。
- ODD 相关邮件优化。
- 余额不足提醒邮件账单金额取值逻辑修改。
- Admin CSM 系统反馈意见处理优化。
- BOI 申报变更为附加服务。
- OpenAPI 文档补充、接口限制和相关后端改造。
- 商户端验证码语言问题修复、注册语言问题修复。

这些工作虽然单个事项看起来相对分散，但都直接影响运营效率、客户体验和问题处理效率。通过持续修复后台使用中的细节问题，可以减少人工沟通成本，也让业务流程更加顺畅。

## 三、协作与交付质量

上半年需求来源广，涉及产品、运营、财务、合规、数据、前端、测试等多个角色。我在协作过程中主要做了以下几方面：

1. 主动梳理需求边界。对于费用、账单、统计、账户结构类需求，优先确认字段来源、计算口径、历史数据处理方式和异常边界，减少开发后返工。
2. 保持跨端一致性。对于 Admin、Gateway、Distributor、OpenAPI 等多端联动需求，配合前端确认接口入参、返回结构、分页查询、模糊搜索和权限判断。
3. 关注测试可验证性。对于费用计算、账单补扣、返现、数据统计等需求，尽量提供清晰的测试路径和样例数据，帮助测试同学覆盖核心场景。
4. 及时处理线上问题。对于短信轰炸限制绕过、资金对账单导出异常、费率申请页面不展示成员客户等问题，能够快速排查原因并推动修复。

从结果上看，今年上半年 120 个 Jira 事项均已关闭，绝大多数冒烟测试通过，整体交付节奏稳定。

## 四、问题与反思

上半年也暴露出一些需要继续改进的地方：

1. 统计口径仍然容易分散。数据看板、月度明细、客户毛利、销售收入、账单算费等需求存在大量相似口径，如果缺少统一沉淀，后续维护成本会持续升高。
2. 账单费用链路复杂度较高。不同卡段、客户类型、费用项、补扣周期叠加后，边界情况较多，需要继续加强规则抽象和测试用例沉淀。
3. 历史数据处理依赖经验。部分需求涉及历史数据清洗和补算，后续可以进一步规范数据修复流程，包括影响范围评估、执行脚本留档、回滚方案和结果核对。
4. 文档沉淀还可以加强。对于账户结构、费用规则、标签规则、统计口径等长期演进模块，需要把关键设计和注意事项沉淀下来，降低后续协作成本。

## 五、下半年计划

下半年我会继续围绕业务稳定交付和系统可维护性提升展开工作：

1. 推动费用和账单能力标准化。继续梳理月结、费率、费用项、补扣、返现等规则，减少硬编码和重复逻辑，提升可配置能力。
2. 完善数据统计口径治理。将客户毛利、渠道成本、销售收入、月度明细等核心指标的来源、计算方式和适用范围沉淀清楚，提升数据可信度。
3. 深化账户与客户体系建设。围绕 API 客户、渠道客户、白标客户、master/sub 结构继续优化查询、权限、合规和管理流程。
4. 提升风控标签能力。继续推进标签规则治理、自动化打标、异常账户处理和风险识别能力，让标签体系更好地服务运营、合规和风控。
5. 加强技术债治理。针对慢接口、历史数据处理、复杂 SQL、公共逻辑分散等问题，结合需求迭代逐步优化，提升系统稳定性和后续研发效率。
6. 补强文档和复盘。对复杂模块形成更完整的接口说明、口径说明、测试说明和问题复盘，减少重复沟通和知识断层。

## 六、总结

2026 年上半年，我的工作重点从单一功能开发逐步扩展到费用账单、数据统计、账户结构、风控标签和公共服务等多条业务主线。通过持续交付和问题处理，我对公司核心业务链路、数据口径和后台系统有了更深入的理解，也在复杂需求拆解、跨团队协作、线上问题定位和系统稳定性建设方面积累了更多经验。

下半年我会继续保持交付质量，同时把更多精力投入到公共能力抽象、数据口径治理、复杂链路文档化和技术债优化上，争取在支撑业务快速发展的同时，让系统变得更稳定、更清晰、更容易维护。
