# 销售毛利报表日维度重构设计稿

## 摘要

销售毛利报表需要支持任意开始日期和结束日期查询，例如只统计每月 10 日至 20 日。当前估算视图和快照按月聚合，丢失了日范围筛选所需的 `report_date`，因此需要将估算视图、汇总快照和明细快照调整为日粒度。用户已确认报表组成项均可取得真实业务日期；本设计统一以该业务日期筛选和归集，不按月初占位、不按天均摊。

本文是日维度重构评审稿，获确认后再据此修改 SQL、批处理脚本和接口查询。

## 1. 目标

- 支持 `startDate`、`endDate` 闭区间查询，日期格式为 `yyyy-MM-dd`。
- 查询结果按销售汇总所选区间内的日数据；明细保留日、客户、产品、渠道和来源维度。
- 继续沿用快照版本机制：`snapshot_date` 表示快照版本日期，`report_date` 表示业务发生日期。
- 所有金额保持源数据符号，负数原样保留，不归零、不截断。
- 保持现有四个接口形态：汇总分页、明细分页、汇总导出、明细导出；四个接口统一使用日期区间条件。

## 2. 非目标

- 首期不新增按实收维度计算的独立毛利指标。
- 不改变销售数据权限、销售名称及账户信息的服务层补齐方式。
- 不在 SQL 中关联 `user` 或 `account` 表。
- 不对负数金额进行归零、绝对值转换或非负约束。

## 3. 指标口径

区间内先按各自 `report_date` 筛选和汇总，再按下式计算：

| 指标 | 公式 |
|---|---|
| `Rebate` | 客户返现 + 代收返现 + 毛利返现 |
| `Pref_Rev_effective` | `Pref_Rev - Rebate` |
| `Pref_GP` | `Pref_Rev - Cost` |
| `Cashflow_Rev_effective` | `Cashflow_Rev - Rebate` |
| `Cashflow_GP` | `Cashflow_Rev - Cost` |
| `Cashflow_Rev_sale_effective` | `Cashflow_Rev_sale - Rebate` |
| `Cashflow_GP_sale` | `Cashflow_Rev_sale - Cost` |

- `Pref_Rev` 为实时收取的各项收入及月账单应收。
- `Cashflow_Rev` 为实时收取的各项收入及历史月账单实收。
- `Cashflow_Rev_sale` 为按现有销售维度规则剔除部分收入后的实收。
- `Cost` 沿用确认后的成本来源及构成。若返现已包含在 `Cost` 中，毛利公式不再额外减一次 `Rebate`。

## 4. 数据粒度和字段

### 4.1 估算视图

估算明细保留 `report_date`，按以下维度形成一行：

`report_date + sale_id + root_account_id + product + provider + metric_code + source_type`

视图同时保留来源需要的 `settlement_month` 作为追溯字段，但查询范围以 `report_date` 为准。销售汇总从该明细按 `report_date + sale_id` 归集。

### 4.2 汇总快照表

日汇总业务粒度：`report_date + sale_id`。建议字段包括 `id`、`snapshot_date`、`report_date`、`sale_id`、各项金额、版本及审计字段。

`id` 的稳定生成输入包含快照版本日期、业务日期和销售 ID。表继续按 `snapshot_date` 分区以保留既有快照版本/回刷模式，并增加以 `report_date`、`sale_id` 开头的查询索引。

### 4.3 明细快照表

日明细业务粒度：`report_date + sale_id + root_account_id + product + provider + metric_code + source_type`。保留 `settlement_month` 供账单归属追溯。

`id` 的稳定生成输入包含快照版本日期、业务日期和全部明细维度；`provider IS NULL` 与具体 provider 分别作为独立业务键。表继续按 `snapshot_date` 分区，并增加日期范围查询索引。

金额列继续使用有符号 `numeric(20,4)`，不加非负约束。

## 5. 快照和查询行为

- 快照运行时间仍沿用现有月度 8 日固化、20 日账单生成后幂等回刷的安排；重跑时沿用同一 `snapshot_date`，以 `report_date` 和业务维度 upsert。
- 快照视图需按业务日期保留每一日数据，不能先 `date_trunc('month', report_date)` 再入快照。
- 任意区间查询按 `report_date >= startDate AND report_date <= endDate` 筛选。
- 查询跨月时，对覆盖到的每个业务日应用相同区间条件，再按销售汇总；快照版本选择规则需在实现中按现有月度版本规则扩展为每个业务月份取最新版本。
- 月度查询是日期区间查询的特例：起止日期为自然月首末日，按日快照聚合得到月数据。

## 6. 接口影响

四个接口请求 DTO 由 `settlementMonth` 改为必填 `startDate`、`endDate`，并验证开始日期不晚于结束日期。分页、导出、筛选项、数据权限和返回指标不变。明细接口继续要求 `saleId`；导出继续沿用现有 `ReportFactory` 策略及分批导出方式。

## 7. 备选方案

1. **日粒度视图和快照（推荐）**：所有来源按真实 `report_date` 入账，支持部分月、跨月区间，整月查询通过日数据汇总。该方案符合用户已确认的日日期来源。
2. 保留月粒度快照，仅增加日期参数：无法从月汇总反推出 10–20 日金额，不满足需求。
3. 将月金额均摊到每日：虽可返回区间值，但会虚构业务日期和日毛利，不采用。

## 8. 实施范围

评审通过后，依次调整：

1. 估算物化视图：保留 `report_date`，重算日粒度金额与稳定 ID。
2. 汇总、明细快照 DDL：增加/替换日粒度字段、查询索引和稳定键说明，保留 2026–2028 分区范围。
3. 8 日快照及 20 日回刷脚本：按日粒度抽取并幂等 upsert。
4. CDC/批处理读取投影、核对 SQL：由月份筛选改为日期范围或目标月份内日数据。
5. Java DTO、Mapper XML、服务和对接文档：四接口统一按闭区间 `report_date` 查询。
