# 销售毛利报表前后端对接文档

> 本文按 `qbit-assets` 当前销售毛利 Controller、DTO、VO 和 Service 实现整理，供 Admin 前端联调使用。接口路径和字段以实际代码为准。

## 1. 基本约定

- 管理端接口前缀：`/api/admin/sale/gross-profit`。
- 四个 HTTP 接口均使用 POST，查询条件和业务参数放在 `application/json` 请求体中。
- 请求按现有后台登录态及网关规则携带认证信息；销售数据范围由后端根据当前用户计算，客户端不传 `allowedSaleIds`。
- 统一响应为 `Result<T>`：`code`、`message`、`data`；成功时 `code=200`、`message="success"`。
- 分页字段为 `current`（从 1 开始，默认 1）和 `size`（默认 20，服务端最大 500）；分页响应使用 MyBatis-Plus `Page` 的 `records`、`total`、`current`、`size`、`pages`。
- `settlementMonth` 和 `reportDateRange` 使用 `yyyy-MM-dd`；结算月份必须是所选月份第一天，报告日期范围首尾均包含。
- 销售名称在查询结果分页后由后端补齐；明细账户对象由后端按 `rootAccountId` 批量回填，不要求前端另行查询。
- 导出接口异步受理，HTTP 成功只表示任务已提交；CSV 完成后通过 `admin_message_notice` WebSocket 通知下载链接。

## 2. 接口清单

| 功能 | 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- | --- |
| 月度汇总分页 | POST | `/api/admin/sale/gross-profit/page` | JSON：分页和筛选条件 | `Result<Page<SalesGrossProfitSummaryVO>>` |
| 销售明细分页 | POST | `/api/admin/sale/gross-profit/detail` | JSON：分页、销售和明细筛选条件 | `Result<Page<SalesGrossProfitDetailVO>>` |
| 月度汇总导出 | POST | `/api/admin/sale/gross-profit/export` | JSON：汇总筛选条件 | `Result<Void>`，异步下载通知 |
| 销售明细导出 | POST | `/api/admin/sale/gross-profit/detail/export` | JSON：明细筛选条件 | `Result<Void>`，异步下载通知 |

请求需按项目现有后台登录态及网关规则携带认证信息。

## 3. 请求参数

四个接口统一使用 POST + application/json，参数通过 @Valid @RequestBody DTO 接收。页面只展示两个时间筛选控件：报告日期范围和结算月份。

前端字段映射：日期范围控件的开始日和结束日按 yyyy-MM-dd 放入 reportDateRange；月份控件选择 yyyy-MM 后转换为该月第一天，放入 settlementMonth，例如 2026-10 转为 2026-10-01。两个时间条件需要同时传给汇总、明细和导出接口。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| settlementMonth | string | 是 | 结算月份日期，格式 yyyy-MM-dd，必须为所选月份第一天；选择 2026 年 10 月后传 2026-10-01。 |
| reportDateRange | string[] | 是 | 报告日期闭区间，格式 yyyy-MM-dd，必须包含开始日和结束日，例如 2026-10-01 至 2026-10-31；筛选数据库 report_date。 |
| saleId | string | 明细接口必填 | 销售 ID。汇总接口可选；明细调用从选中的汇总行带入，不作为页面筛选控件。 |
| rootAccountId / product | string | 否 | 可选的客户根账户、产品筛选参数；当前页面不展示这些筛选控件。provider 和 metricCode 不作为请求筛选字段。 |
| current | integer | 否 | 页码，从 1 开始，默认 1；分页接口使用。 |
| size | integer | 否 | 每页条数，默认 20，最大 500；分页接口使用。 |

current 和 size 是分页控制，不是筛选条件。allowedSaleIds 是服务端权限字段，客户端不要提交。导出接口不需要分页字段；服务端会循环分页读取全部匹配结果，并合并生成一个 CSV。

### 汇总分页

`POST /api/admin/sale/gross-profit/page`

Content-Type: `application/json`

请求示例：

```json
{
  "settlementMonth": "2026-10-01",
  "reportDateRange": ["2026-10-01", "2026-10-31"],
  "current": 1,
  "size": 20
}
```


指定销售筛选：

`POST /api/admin/sale/gross-profit/page`

```json
{
  "settlementMonth": "2026-10-01",
  "reportDateRange": ["2026-10-01", "2026-10-31"],
  "saleId": "{saleId}",
  "current": 1,
  "size": 20
}
```


### 明细分页

`POST /api/admin/sale/gross-profit/detail`

Content-Type: `application/json`

请求示例：

```json
{
  "settlementMonth": "2026-10-01",
  "reportDateRange": ["2026-10-01", "2026-10-31"],
  "saleId": "{saleId}",
  "current": 1,
  "size": 20
}
```


页面传入两个时间条件；明细接口还需带入 saleId。日期范围两端均包含。

### 汇总导出

`POST /api/admin/sale/gross-profit/export`

## 4. 分页响应

分页接口返回 Result<Page<T>>。Page 常用字段为 records、total、current、size 和 pages。

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "records": [],
    "total": 0,
    "current": 1,
    "size": 20,
    "pages": 0
  }
}
```

金额以十进制数值返回。前端展示时应避免使用二进制浮点数重新计算金额。收入、返现、成本和毛利均保留来源正负号。

### 明细账户信息

明细 VO 参考 `QuantumAccountRankingVO` 实现 `Serializable, IAccount`。API 只返回客户根账户 ID 和账户对象：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| rootAccountId | string/null | 客户根账户 ID，来自毛利明细查询结果。 |
| account | object/null | 后端通过 `AccountService.relation(records)` 批量回填的账户对象。 |

账户信息在查询分页完成后回填，不参与金额聚合或 SQL 分页。Mapper 只查询 DWS 中的 `rootAccountId`，不直接关联 `account` 或 `user` 表。服务端复用 `IAccount` 关系查询时，内部将 `rootAccountId` 映射为账户查询 ID；该兼容属性不序列化为 `accountId`。`account` 对象结构遵循项目现有 `Account` 实体及 `AccountService` 回填逻辑；账户不存在时为 `null`。接口不返回 `accountId` 和 `kycCaseId`。

明细响应中的账户字段示例（`account` 仅展示部分属性）：

```json
{
  "rootAccountId": "root-account-id",
  "account": {
    "id": "root-account-id",
    "verifiedName": "示例客户",
    "displayId": "customer-display-id"
  }
}
```

## 5. 数据来源和页面行为

- 如果结算月份已有未软删除的快照，接口读取该月最新 snapshot_date 对应的数据版本。传入 reportDateRange 时，明细和汇总都按明细快照中的 report_date 闭区间过滤；汇总快照没有 report_date，因此汇总从同一最新版本的明细快照按销售重新聚合。
- 生产环境没有该月快照时会回退到近期估算视图，返回记录的 dataStatus 为 ESTIMATE。
- 非生产环境没有快照时返回空分页，不读取生产估算视图。测试环境需要先准备对应月份的快照数据。
- 空分页没有记录，因此不会有记录级 dataStatus；页面应按 records 为空处理。
- 汇总和明细查询使用数据库分页，size 会被限制在 500 以内。
- 客户端指定的 saleId 不在当前用户授权范围时，服务端返回 HTTP 403；未指定 saleId 的汇总查询按当前用户权限范围过滤。
- 测试环境若通过 SQL 修改快照的 sale_id 或 root_account_id，会改变接口显示归属和筛选结果。此类 SQL 属于测试数据准备，不属于 HTTP 接口契约。

## 6. 导出响应与处理

汇总和明细导出均为异步任务。接口校验并受理请求后立即返回成功，不在 HTTP 响应中返回文件地址；后台按请求的所有筛选条件循环分页读取完整结果，将全部记录合并成一个 CSV，不打 ZIP。

分页接口的 `current` 和 `size` 不影响导出范围，导出始终包含当前筛选条件下的全部数据。请求线程会捕获当前登录用户，后台分页查询继续使用该用户的数据权限。导出 Handler 每页读取 500 条，不断翻页直到无记录，再将结果合并为一个 CSV。

```json
{
  "code": 200,
  "message": "success",
  "data": null
}
```

成功响应表示导出任务已受理，不代表 CSV 已生成完成。CSV 生成后，后端向 `admin_message_notice` 推送一次下载通知，通知内容包含 CSV 下载链接。无匹配记录时仍生成仅含表头的 CSV 并通知下载；任务异常时推送失败通知。前端应保留现有 WebSocket 通知处理，并引导用户从通知中下载文件，不要从 HTTP 响应中读取 `downloadUrl`。

汇总与明细导出分别使用独立的 `SalesGrossProfitSummaryExportBO` 和 `SalesGrossProfitDetailExportBO`，不直接用分页响应 VO 作为 CSV 行对象。CSV 表头均为英文；金额沿用原始正负号。

汇总 CSV 列按以下顺序输出：

| CSV 表头 | 数据来源 / 说明 |
| --- | --- |
| `Month` | 结算月份 `settlementMonth`。 |
| `BD` | 销售名称 `saleName`；汇总导出不包含销售 ID。 |
| `Pref_Rev` | 应收总收入 `prefRev`。 |
| `Client_Rebate` | `clientRebate + grossProfitRebate`；毛利返现合并在客户返现中，不单独导出。 |
| `Client_Collection_Rebate` | 代收返现 `clientCollectionRebate`。 |
| `Rebate` | 返现合计 `rebate`。 |
| `Pref_Rev_effective` | 应收有效收入 `prefRevEffective`。 |
| `Cost` | 总成本 `cost`。 |
| `Pref_GP` | 应收毛利 `prefGp`。 |
| `Cashflow_Rev_sale` | 销售维度收入 `cashflowRevSale`。 |
| `Cashflow_Rev_sale_effective` | 销售维度有效收入 `cashflowRevSaleEffective`。 |
| `Cashflow_GP_sale` | 销售维度毛利 `cashflowGpSale`。 |

明细 CSV 列按以下顺序输出：

| CSV 表头 | 数据来源 / 说明 |
| --- | --- |
| `Month` | 结算月份 `settlementMonth`。 |
| `Sale_ID` | 销售 ID `saleId`。 |
| `BD` | 销售名称 `saleName`。 |
| `Customer_Name` | 账户名称 `account.verifiedName`。 |
| `Display_ID` | 账户展示 ID `account.displayId`。 |
| `Product` | 产品 `product`。 |
| `Provider` | 渠道或服务商 `provider`。 |
| `Pref_Rev` | 应收收入 `prefRev`。 |
| `Client_Rebate` | `clientRebate + grossProfitRebate`；不单独导出毛利返现。 |
| `Client_Collection_Rebate` | 代收返现 `clientCollectionRebate`。 |
| `Rebate` | 返现合计 `rebate`。 |
| `Pref_Rev_effective` | 应收有效收入 `prefRevEffective`。 |
| `Cost` | 总成本 `cost`。 |
| `Pref_GP` | 应收毛利 `prefGp`。 |
| `Cashflow_Rev_sale` | 销售维度收入 `cashflowRevSale`。 |
| `Cashflow_Rev_sale_effective` | 销售维度有效收入 `cashflowRevSaleEffective`。 |
| `Cashflow_GP_sale` | 销售维度毛利 `cashflowGpSale`。 |

这里仅调整 CSV 导出 BO 和表头，不改变分页 API VO：API 响应仍保留 `clientRebate`、`clientCollectionRebate`、`grossProfitRebate` 等独立来源字段。CSV 不导出 `rootAccountId`、`accountId` 或 `kycCaseId`。

CSV 文件名以发起用户 ID 和导出发起时间开头，格式为 `userId_yyyyMMddHHmmss`；后续保留报表类型和结算月份，明细文件还包含 saleId。例如 `u123_20261104153045_销售毛利汇总_2026-10-01.csv`。CsvService 会在存储路径追加毫秒时间戳，以避免重复导出覆盖。

单文件生成前会将分页结果暂存在内存中，处理方式与自然人黑名单导出的全量单文件模式一致；如果明细数据规模明显增大，应评估改用流式 CSV 写入。

## 7. 校验和错误处理

- settlementMonth 必须是有效日期且为所选月份第一天，例如 2026-10-01。
- reportDateRange 必须包含两个有效日期，开始日不能晚于结束日。
- 明细查询或明细导出缺少 saleId 时返回 HTTP 400。
- 未登录或数据权限校验失败时按后台统一鉴权及业务错误格式处理。
- 前端应同时检查 HTTP 状态码和响应体 code；成功响应 code=200。

## 8. 推荐页面调用流程

1. 页面打开或结算月份变更时调用汇总分页接口。
2. 用户点击销售行时，将该行 saleId 带入明细分页接口。
3. 日期范围或结算月份变化时重置 current=1 并重新查询汇总；打开明细时从选中的汇总行带入 saleId，同时沿用两个时间条件。
4. 导出时提交当前筛选条件；明细导出必须带 saleId。提交后按成功响应提示任务已开始，最终下载链接通过 WebSocket 通知到达。
