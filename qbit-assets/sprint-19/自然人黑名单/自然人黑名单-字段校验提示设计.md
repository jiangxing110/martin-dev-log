# 自然人黑名单错误码校验设计

## 目标

手工新增、导入检查和导入确认共用身份校验与冲突判断；所有字段级提示均由错误码平台配置提供，中文、英文以及品牌文案保持一致。

## 错误码映射

| 数字码 | 场景 | 规则 |
|---|---|---|
| `11010101045` | 邮箱格式错误 | 复用邮箱规范化校验 |
| `11010101046` | 国籍代码错误 | 必须是有效 ISO 3166-1 alpha-2 代码 |
| `11010101047` | 证件类型不受支持 | 仅接受系统现有证件类型 |
| `11010101048` | 证件维度不完整 | `countryCode`、`idType`、`documentNumber` 任意一项有值时，三项都必须填写 |
| `11010101049` | 邮箱重复 | 活动黑名单中已有相同规范化邮箱 |
| `11010101050` | 证件重复 | 活动黑名单中已有相同的国籍 + 证件类型 + 证件号 |
| `11010101051` | 加黑原因无效 | 加黑原因不能为空且最多 255 个字符 |
| `11010101052` | 导入行写入失败 | 未分类的单行写入失败，不影响其他行 |

错误提示从 `自然人黑名单-错误码配置草案.json` 加载，不在业务代码中硬编码。`11010101041`保留为未识别重复冲突的兜底码；`11010101042`用于未提供任何身份信息或未细分身份校验失败；`11010101052`用于未分类的导入行写入失败。

## 行为

- 一次请求有多个错误时按既定校验顺序返回首个错误。
- 同一错误在新增 API、导入检查行和导入确认行返回同一个错误码及平台配置文案。
- 导入继续按行部分成功；错误只影响当前行。
- 证件号码目前只做非空、首尾空白处理和大小写规范化；没有新增按国家/证件类型定制的号码格式规则。
- 不改变 Excel 字段、身份匹配规则或黑名单写入行为。

## 实现方案

错误语义由 `BlacklistValidationErrorEnum` 表示，服务层将错误码转换为 `ExceptionCodeFactory` 业务异常；导入结果直接使用异常中由平台解析出的本地化消息。重复身份也按身份维度返回对应错误码。
