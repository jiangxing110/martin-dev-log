> 更新时间：2026-10-28

> 状态：Assets 目标分支已提交并推送（`853f47f1bd`）；本次未编译或运行测试。Node 仓库状态沿用下文既有记录。

## 摘要

本次完成自然人黑名单管理端能力和 Node KYC 实时校验接入。Assets 负责名单管理、导入检查与确认、命中查询、解除、异步明文导出及处置加黑 Service；Node 在 API KYC 和 SumSub KYC 创建前查询同一组 `public` 表，命中时记录事件和统一操作日志并拒绝认证。

数据库结构定义在 `natural_person_blacklist.sql`，包含名单主表、身份维度表和命中事件表。数据库明文保存身份值；列表和命中快照使用脱敏值。

## 1. Assets（Java）改动

### 1.1 管理端接口

新增 Controller：

`qbit-core/src/main/java/com/qbit/admin/naturalperson/blacklist/controller/NaturalPersonBlacklistAdminController.java`

接口清单：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/admin/natural-person-blacklists` | 手工新增名单 |

### 1.2 名单和身份处理

新增领域代码位于 `qbit-core/src/main/java/com/qbit/admin/naturalperson/blacklist/`，主要包括 Controller、DTO/VO、Entity、Mapper、Service、导入和导出处理器，以及身份规范化、脱敏和转换工具。

- 名单支持 `MANUAL`、`IMPORT`、`DISPOSITION` 三种来源，状态为 `ACTIVE`、`RELEASED`。
- 身份维度独立保存：邮箱单独匹配；证件按“国籍 + 证件类型 + 证件号”组合匹配；一条名单可以包含邮箱、证件或两者。
- 邮箱去首尾空格并转小写；证件号去首尾空格并转大写；国籍转大写并校验 ISO alpha-2；证件类型归一到系统现有枚举名称。
- 查询列表和详情返回脱敏身份值；明文查询单独提供接口，并记录操作日志。明文导出使用现有异步导出框架，并记录导出操作。
- 活动身份通过唯一索引限制重复；名单/身份采用软删除字段，不创建物理外键。
- 新增 `NaturalPersonBlacklist` 操作日志业务类型，记录新增、详情/明文查询、命中查询、解除和导出等操作。

### 1.3 导入与导出

- 支持 `.xls`、`.xlsx`，最多 5000 行。
- `imports/check` 逐行校验格式、文件内重复和数据库活动身份冲突；只返回预览，不写入名单或操作日志。
- 检查阶段生成 `IMP-日期-雪花ID` 批次号；批次号保存在导入名单的 `import_batch_no` 字段。**没有新增导入批次表**。
- `imports/confirm` 再次逐行校验并写入；采用部分成功，单行失败不阻断后续行，回执返回成功/失败数量、逐行错误和成功名单 ID。
- 异步导出沿用 Assets 现有 ReportFactory/ExportService 机制，导出匹配筛选范围内的明文身份信息。

### 1.4 处置联动

`NaturalPersonBlacklistService.addFromDisposition(...)` 提供给删除处置调用方的内部 Service 方法，不新增 HTTP 接口。调用方传入身份信息、处置业务类型、处置业务 ID 和关联账户 ID；加黑失败处理及幂等由调用方负责。

## 2. Node（`qbitpay_service`）改动

### 2.1 Entity 和 TypeORM 注册

新增实体目录：`src/entity/cdd/natural-person-blacklist/`

- `natural-person-blacklist.entity.ts`：映射 `public.natural_person_blacklist`。
- `natural-person-blacklist-identity.entity.ts`：映射 `public.natural_person_blacklist_identity`。
- `natural-person-blacklist-hit.entity.ts`：映射 `public.natural_person_blacklist_hit`。
- `natural-person-blacklist.enum.ts`：名单状态、来源和身份维度枚举。

三个表均显式映射 `public` schema，并设置 `synchronize: false`，避免 TypeORM 自动修改表结构。`bigint` ID 使用字符串承载，避免 JavaScript number 精度损失。实体已加入 `src/modules/entity-register/entity-register.module.ts`。

### 2.2 KYC/SumSub 校验

新增 `src/modules/cdd/blacklist/natural-person-blacklist.service.ts`，在 `KycIndividualV2Service` 的两个入口调用：

1. `sourceType=api`：用 API 提交的证件信息和主账户邮箱，在创建 KYC 记录前检查。
2. `sourceType=sumsub`：导入并读取 SumSub applicant 资料后，在创建 KYC 记录前检查。

匹配条件与 Assets 一致：邮箱不区分大小写；证件匹配要求国籍、规范证件类型和证件号全部相同；只检查未软删除且处于活动状态的身份及名单。

命中后在同一数据库事务中写入 `natural_person_blacklist_hit` 和 `operationLog`，然后返回统一认证拒绝提示 `认证未通过，证件存在风险`，不向认证用户暴露名单 ID 或匹配维度。查询、命中记录或日志写入失败时 fail-closed，返回错误码 `11010101040`，不继续 KYC。

新增 Node 操作日志业务类型 `NaturalPersonBlacklist`。命中日志关联名单 ID，并只记录场景、来源和命中的维度类型，不记录证件原文或邮箱原文。命中快照存脱敏值；其中名单 bigint ID 以 JSON 数字形式存储，兼容 Assets 侧按名单 ID 查询命中记录。

## 3. 数据库 SQL

完整 DDL：[`natural_person_blacklist.sql`](./natural_person_blacklist.sql)

命中记录样例数据：[`natural_person_blacklist_hit_seed.sql`](./natural_person_blacklist_hit_seed.sql)，按接口返回的 8 条名单生成 30 个测试命中事件，每条名单对应 3 或 4 次命中，包含邮箱/证件脱敏快照。表被删除时脚本会按当前结构重建命中表和索引，然后执行 3 条独立 INSERT、每条 10 条记录；不包裹 `BEGIN`/`COMMIT`，不包含旧字段；`request_id` 可为空以支持持卡人创建前校验；固定 ID，成功执行的 INSERT 不要重复执行。脚本仅生成，未在数据库执行。

脚本创建三张表：

| 表 | 用途 |
| --- | --- |
| `public.natural_person_blacklist` | 名单生命周期、状态、来源、导入批次号和解除信息 |
| `public.natural_person_blacklist_identity` | 邮箱或证件匹配维度；保存原文、规范化值和脱敏值 |
| `public.natural_person_blacklist_hit` | 永久保留命中事件、来源、账户及脱敏匹配快照 |

脚本包含字段中文注释、活动身份唯一索引、查询索引及命中快照 GIN 索引。DDL 也保留在 Assets 仓库：`qbit-core/src/main/resources/sql/natural_person_blacklist.sql`。

## 4. 错误码

Assets 在 `CodeConstant` 中增加以下号码：

| 错误码 | 当前用途 |
| --- | --- |
| `11010101039` | 自然人黑名单命中；Node KYC 命中拒绝 |
| `11010101040` | 黑名单校验不可用；Node 数据库检查或命中记录失败时 fail-closed |
| `11010101041` | 身份信息冲突 |
| `11010101042` | 身份信息无效 |
| `11010101043` | 导入文件或导入批次参数无效 |
| `11010101044` | 名单记录不存在 |
