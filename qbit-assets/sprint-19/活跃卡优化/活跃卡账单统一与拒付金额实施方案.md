# 活跃卡账单统一处理与金额拒付历史配置 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 通过共享服务提供直客/API 活跃卡账单费用与 ZIP 明细查询，并将金额拒付数据写入 API 账单历史配置。

**Architecture:** 新增一个具体的活跃卡账单服务类集中处理汇总、费率计算和逐卡明细查询；保留按用途的 Mapper 汇总/明细查询，并由调用方传入现有费率类型以保持收费行为。API 风控查询已有拒付金额和无验证消费金额，将其与金额拒付率透传至 `ApiBillHistoryConfig`。

**Tech Stack:** Java 17、Spring Boot 3、MyBatis-Plus、FastJSON。

**Spec:** `docs/superpowers/specs/2026-10-25-active-card-bill-and-reject-rate-design.md`

## Global Constraints

- 新代码使用 `@RequiredArgsConstructor` 和 `private final` 构造器注入。
- 新增类和公开方法有中文注释及 `@author`；新字段写准确中文 Javadoc。
- 保留直客/API 现有费率类型、计费规则与 PDF 表现。
- 不自动创建分支、commit、push、合并或 PR。

## Review Focus

- 直客和 API 活跃卡费继续使用各自既有 `AccountFeeType`，避免费率来源变化。
- 活跃卡汇总仍采用按账户/provider 聚合查询，ZIP 明细仍采用逐卡查询。
- 起止账期、provider 映射、PC 豁免月份与 LS/未知渠道处理保持原状。
- 新增金额值沿用原始风险查询结果，不从已处理的比率反推。
- 旧 `bill_history_config` 缺少新增字段时仍可读取，新增字段不进入 PDF 参数。
