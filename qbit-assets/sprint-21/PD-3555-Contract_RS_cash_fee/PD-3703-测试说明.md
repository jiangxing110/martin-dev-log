# PD-3703 合同 RS 返现及 AccountFee 测试说明

## 1. 测试目标

验证以下行为：

1. 创建或修改合同前，QI/BZ RS 毛利返现不能与同渠道 NR 消费返现配置重叠的有效期。
2. 合同审核并签署生效后，QI/BZ RS 合同费率进入 CAAS 下发链路。
3. RS 合同费率下发成功时，对应 Scheme Fee 默认费率写入 `account_fee`，provider、费率类型和有效期正确。
4. QI、BZ 两组默认费率互不覆盖；没有 RS 合同时不额外创建默认费率。

## 2. 环境和数据准备

- 使用 QA/测试环境，不要在生产账户上执行。
- 准备一个可创建 CAAS 合同、可审核且可使用 DocuSign 测试环境的账户。
- QI 单渠道、BZ 单渠道、QI+BZ 双渠道、NR 冲突和无 RS 场景尽量使用不同的测试账户，避免旧 `account_fee` 记录影响数量核对。
- 记录账户 ID、合同 ID、合同费率有效期以及测试前该账户的 QI/BZ RS、NR 和 Scheme Fee 记录。
- 测试账号需具备后台合同创建/修改权限，以及 BD、法务审核权限。

## 3. 合同互斥校验

合同费率清单在保存合同前校验。后台入口：

- 创建/提交：`POST /api/admin/contract/save`
- 修改：`POST /api/admin/contract/update`

推荐通过后台页面操作；如使用 API，应基于接口完整必填对象，只替换 `contractAccountFeeDTOList` 中的相关费率项。关键字段结构如下：

```json
{
  "feeType": "QuantumCardQIRSProfitCashBack",
  "startTime": "2026-06-01T00:00:00.000Z",
  "endTime": "2026-12-01T00:00:00.000Z"
}
```

`feeType` 使用枚举的接口值。QI/BZ RS 与 NR 对应值：

| 渠道 | RS 毛利返现 | NR 消费返现 |
| --- | --- | --- |
| QI | `QuantumCardQIRSProfitCashBack` | `QuantumCardQIConsumptionCashBack` |
| BZ | `QuantumCardBZRSProfitCashBack` | `QuantumCardBZConsumptionCashBack` |

### 校验用例

| 用例 | 合同费率清单 | 预期 |
| --- | --- | --- |
| V1 | QI RS 与 QI NR 有效期重叠 | 保存失败，提示两项费率有效期重叠；不生成合同申请 |
| V2 | BZ RS 与 BZ NR 有效期重叠 | 保存失败，提示两项费率有效期重叠；不生成合同申请 |
| V3 | QI RS 与 BZ NR 同期 | 允许保存；不同渠道互不冲突 |
| V4 | QI RS 与 QI NR 有效期不重叠 | 允许保存 |
| V5 | QI RS 结束时间与 QI NR 开始时间相同 | 拒绝；区间端点相接按重叠处理 |
| V6 | 同一有效期只配置 QI RS 或 BZ RS | 允许保存 |
| V7 | 修改已有合同，把互斥费率改为有效期重叠 | 更新失败，原合同数据保持不变 |

注意：空开始或结束时间在当前校验中按无边界处理。测试重叠场景时应显式填入有效期，避免数据缺省影响判断。

## 4. 审核、签署及自动下发

有效合同费率应经过完整合同生命周期后再核对账户费率：

1. 用 V6 的有效配置创建合同，保存并记录合同 ID。
2. 确认合同申请进入审核流程。
3. 按测试环境流程完成 BD Leader 审核和法务审核。接口分别为：
   - `POST /api/admin/contract-apply/bd-leader/review`
   - `POST /api/admin/contract-apply/legal/review`
4. 在 DocuSign 测试环境完成双方签署。
5. 等待签署回调完成，或等待合同状态轮询将合同更新为生效。
6. 确认合同审核状态为已完成、合同状态为生效后，系统触发合同费率下发。
7. 检查合同下发任务及明细：
   - `contract_fee_dispatch_task`：按 `contract_id` 查任务状态、费率数量、成功/失败产品线和错误信息。
   - `contract_fee_dispatch_detail`：按 `contract_id` 查 CAAS 业务线状态、请求/响应快照和失败原因。
8. 只有下发成功后再核对 `account_fee`。合同未生效、未完成签署或下发任务失败时，不应据此判定默认费率写入失败。

自动下发的触发点包括 DocuSign 合同签署完成，以及合同状态轮询发现合同已完成且状态转为生效。正常端到端测试优先走签署回调。

## 5. AccountFee 核对

`AccountFee` 实体映射到 PostgreSQL 的带引号表名 `"accountFee"`。用数据库客户端按账户、费率类型和 provider 核对。示例：

```sql
SELECT "feeType", "provider", rate, "mathType", low, high,
       "startTime", "endTime", "deleteTime"
FROM "accountFee"
WHERE "accountId" = '<测试账户ID>'
  AND "deleteTime" IS NULL
  AND "feeType" IN (
      'QuantumCardQIRSProfitCashBack',
      'QuantumCardBZRSProfitCashBack',
      'IssuerTransactionFeesByAuthInt',
      'IssuerTransactionFeesByAuthInt_Caas',
      'IssuerTransactionFeesSettlementInt',
      'IssuerTransactionFeesSettlementInt_Caas',
      'IssuerCardServiceFeesInt',
      'IssuerCardServiceFeesInt_Caas',
      'VisaRiskManagerInt',
      'VisaRiskManagerInt_Caas',
      'SchemeSignatureFee_Caas'
  )
ORDER BY "provider", "feeType", low;
```

预期检查：

- QI RS 合同：写入 32 条 `provider = 'QbitIssuing'` 的默认费率，不写 BZ `I2c` 默认费率。
- BZ RS 合同：写入 21 条 `provider = 'I2c'` 的默认费率，不写 QI `QbitIssuing` 默认费率。
- QI+BZ RS 合同：共 53 条，QI 32 条、BZ 21 条，分别归属各自 provider。
- 默认费率 `startTime` / `endTime` 与对应 RS 合同费率有效期一致。
- QI 的 Auth、Settlement、Service 费率应分别保留 5 个阶梯，最高阶 `high` 为空；VRM 是单档。
- BZ 费率应为单档；仅 CAAS Scheme Signature Fee 有默认值 0.04。
- 不应出现相同账户、provider、feeType 的重复有效记录。重试/重复下发后再次核对当前有效记录数与原结果一致。

`feeType` 的数据库值采用枚举接口值；不同环境若数据源已有历史行，先按 `createTime`、`deleteTime` 和 provider 区分本次写入，不要只看总行数。

## 6. 无 RS 和隔离回归

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| V8 无 RS | 新账户创建并签署只包含 NR 或其他费率的合同 | 合同费率正常下发，不因本需求生成 QI/BZ Scheme Fee 默认费率 |
| V9 渠道隔离 | 只配置 QI RS | 只出现 QI provider 默认费率 |
| V10 渠道隔离 | 只配置 BZ RS | 只出现 BZ provider 默认费率 |
| V11 双渠道 | 同一合同分别配置 QI RS、BZ RS | 两个 provider 的默认费率各自齐全，无交叉删除/覆盖 |
| V12 事务失败 | 在隔离测试环境模拟默认费率批量保存失败 | 事务回滚；合同费率批次和默认费率批次不能留下部分成功数据；下发任务记录失败 |

## 7. 自动化测试与执行说明

代码中新增的 `ContractFeeValidatorTest` 覆盖 QI/BZ 冲突、跨渠道允许和有效期不重叠；默认费率、产品线映射和事务写入另有对应单测。

本说明编写时没有运行编译或测试。若后续允许跑自动化测试，建议先执行目标测试，再按仓库规范进行统一构建验证；数据库事务行为仍需在隔离数据库环境做端到端确认。

## 8. 账户现有费率与兼容日期补充

- 创建、修改和重新发起合同前，除检查本次合同费率清单外，还会按账户 ID 查询 `account_fee` 中 QI/BZ RS 与对应 NR 费率；有效期重叠则拒绝，不重叠则允许。该检查针对账户当前已写入的费率，不读取尚未下发到 `account_fee` 的其他待审核合同。
- 补充跨合同用例：先准备账户当前有效的 QI NR 费率，再提交有效期重叠的 QI RS 合同，应拒绝；将 RS 开始时间调整到 NR 到期之后，应允许。
- 合同修改的互斥校验应在作废已有 DocuSign envelope 前执行。用一份存在 envelope 的合同提交冲突费率，确认请求失败且原 envelope 仍有效。
- 默认 Scheme Fee 的日期沿用 Node 端缺省逻辑：RS 费率没有开始时间时取当前时间；没有结束时间时取本地时间 `2099-02-01 23:59:59`。测试默认日期继承和缺省日期两种情况。
- CAAS 产品线映射自动化测试位于 `StaticFeeTypeProductLineProviderTest`。
