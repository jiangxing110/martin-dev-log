# 自动化打标开发记录

记录当前自动化打标实现、规则周期与 VIP 净消费改动，供代码评审和后续接续开发使用。

## 当前实现概况

- 规则来源分为自定义规则和系统预置规则；系统预置规则通过稳定 `ruleCode` 路由到策略，目前登记 37 个规则编码，策略按业务大类复用。
- XXL-JOB 使用同一个每日任务入口。预置规则有周期元数据，未特别指定时为每日执行；当前只有客户价值分层 / VIP 标记为每月 1 日执行。
- 任务支持按规则 ID、来源类型、规则编码、末级标签 ID/名称及账户 ID 列表筛选。带规则或标签筛选时必须提供账户 ID，任务直接写标签和命中日志。
- 候选账户查询排除 `ApiClientCustomer`（API 子户）；VIP 净消费统计将 API 子户交易归并至母户。
- 自动打标只能关联有效末级标签。规则执行按账户分页；VIP 单规则执行时跳过与 VIP 无关的 KYB、KYC、店铺、产品及 Infinity Launch 上下文查询。
- 自动撤销不再命中的旧标签、同一维度只保留一个结果，仍未实现。

## 本轮更新：周期与 VIP 净消费

### 执行周期

XXL-JOB 任务保持每日 0 点触发。执行器按预置规则周期过滤：日常规则每日执行，月度规则在上海时区每月 1 日执行。当前需求中明确的月周期只有 VIP；卡净消费与渠道毛利 Top10 是 VIP 的两个触发条件。分销规则的“月均”是统计窗口，需求仍标注每日轮询。

月度规则可在周期外手动补跑：任务参数明确传入该规则的 `ruleCode` 或 `ruleId`，并同时提供账户 ID 列表。计划新增其他月周期规则时，只需在规则枚举中声明周期，由统一执行器处理。

### VIP 净消费

- 统计前 3 个完整自然月，使用 `qbit_card_transaction.createTime`。
- 交易状态为 `Closed` 或 `Pending`；净消费按消费减撤销、退款计算。
- API 子户交易通过 `api_account_relation.root_id` 归并至母户。
- SQL 接收 VIP 门槛，直接筛选净消费严格大于门槛的账户。
- VIP 门槛通过 `SystemConfigKeyEnum.VIP_NET_CONSUMPTION_THRESHOLD` 从当前环境的 `systemConfig` 读取，并缓存在服务实例中。
- 生产环境门槛为 1,000,000，其他环境为 10,000。SQL 初始化文件位于本目录；每个环境只执行对应脚本。
- 当前代码实现了卡净消费分支；需求文档中的渠道毛利 Top10 分支尚未接入计算。
