# 自动化打标开发方案

**文档状态：**需求方案评审稿。确定的规则、建议的系统行为和待业务确认事项分开列出；未确认的条件不进入可启用规则。

## 1. 目标与交付范围

在现有自动打标能力上，补齐系统预置规则、定时初始化与重算、互斥维度收敛、标签失配撤销、定向试跑及规则来源管理；同时修复新用户全量信息的客户标签展示和筛选问题。

本方案不实现原需求明确划掉的事件驱动打标。高潜/普通价值分层原文标注“不做”，是否改为本期需求尚待确认；不为 Treasury、White Label、数币收单等缺少条件的项目臆造规则。

## 2. 当前系统与差距

- 已有 `tag_auto_rule` 规则表、Admin 规则 CRUD、规则命中日志、逻辑树校验和 `auto_tag_rule_job` XXL-JOB 入口。
- 当前规则引擎只开放客户行业、客户类型、加密资产 KYB 三类字段；定时任务查询所有启用规则并执行。
- 当前表/实体没有规则来源字段，现有行无法区分系统预置和自定义规则。实际规则条数应以运行环境数据库为准，仓库没有可作为生产规则清单的初始化 SQL。
- 当前执行器主要补写命中标签，尚未按规则失配撤销旧自动标签，也没有维度互斥收敛。
- XXL-JOB 入口读取了任务参数，但未传给执行服务，现阶段传参不会筛选规则或账户。
- 现有规则保存校验已限制目标为末级标签；其他写入和预置加载入口需复用同一校验。
- 原需求还包含新用户全量信息标签展示为空、筛选仅展示合规标签的问题，纳入本次交付。

## 3. 规则目录

- 客户类型、行业分类、产品类型规则目录如下。表中 `标签路径` 描述业务层级，实际写入时必须映射至系统标签树中对应的末级叶子标签 ID；路径中某层在系统标签树不存在时不得自行创建父标签或把父标签当目标。
- 当前按规则项统计共 **35 项**：客户类型与客户价值 5 项、客户行业 21 项、产品类型 9 项。此数不等于末级标签 ID 数量；例如 API 对接模式一项规则映射三个叶子标签。高潜/普通原需求已标注“不做”，暂不计入，是否纳入本期待业务确认；White Label、Treasury 暂无完整判定条件不启用；数币收单作为条件待补齐的规则项计入目录。

## 4. 统一打标行为

### 4.1 标签目标

所有规则必须映射到 `system_tag` 中活动的末级叶子标签 ID。父级、已删除、停用或无法唯一确认的标签均不得写入；执行时不通过名称模糊匹配目标标签。

### 4.2 互斥维度

同一客户的自动标签按以下维度收敛，每个可确定维度最多保留一个自动结果：

- 合作模式：直客、Distributor、MOR、Gateway。
- 合规分类：crypto、non-crypto。
- 客户价值分层：VIP、高潜、普通。高潜/普通的实施范围与条件待确认。

行业分类和产品使用标签不属于上述互斥组，可按规则分别命中多个末级标签。

### 4.3 生命周期与数据不完整

- 规则命中：新增自动标签；目标标签已存在则保持幂等。
- 规则明确失配：撤销由自动规则产生的过期标签，并记录撤销动作。
- 数据缺失、查询失败或状态未知：按“未知”处理，保留现有自动标签并记录原因；不得把未知直接当作失配。
- 互斥维度切换：先计算该维度全部有效规则的期望结果，再统一新增、保留或撤销，不能只按单条规则局部清理。若多个末级标签规则同时命中，必须按经确认的优先级处理；没有明确优先级时不任意选一个，记录冲突并跳过该维度写入。
- 默认只管理自动规则来源标签，不删除人工标签。若人工标签也必须参与强互斥，须另行确认授权和优先级。

### 4.4 调度

- 初始化：上线时分批覆盖历史有效客户，可断点续跑。
- 每日任务：北京时间每日 0 点重算日频静态规则及每日交易规则。
- VIP 月度任务：每月 1 日计算 VIP；卡净消费与毛利周期按确认后的口径执行。
- 不实现事件驱动触发。任务间使用 Redisson 锁；夜间批处理仍须防止重复和并发执行。

## 5. 规则与数据模型改造

### 5.1 `tag_auto_rule`

增加并映射以下元数据：

- `rule_type`：`SYSTEM_PRESET` / `CUSTOM`，标识规则来源。现有记录迁移后默认 `CUSTOM`。
- `rule_code`：系统预置规则的稳定编码；自定义规则为空。用于预置规则身份校验和目录关联，不依赖规则名或标签名。
- 新旧规则的 `raw_data` 统一使用现有 `TagRuleRawDTO` 结构 `{"logicTree": ...}`；`rule_type` 区分 `CUSTOM` 和 `SYSTEM_PRESET`，`rule_code` 列标识具体系统规则。系统规则 JSON 不再另存 `ruleCode`、`targetPath`、`conditionPending` 等另一套结构；标签目标由 `system_tag_id` 绑定，未完成的条件由规则状态保持停用并在规则说明中标明。
- 新旧规则保持 `TagRuleRawDTO` 的 JSON 外壳 `{"logicTree": ...}` 一致，但规则执行根据 `rule_type` 分流：`CUSTOM` 使用现有通用逻辑树；`SYSTEM_PRESET` 由 `rule_code` 对应的预置规则策略计算。系统规则树中的 `system_rule_code` 是统一结构下的路由节点，需在代码中补充字段枚举与预置策略解析；当前版本尚不支持该字段，所有预置记录必须保持停用。
- 互斥组及规则频率等属性仅在确实需要持久化配置时增加，先核对现有生产表结构，避免重复存储可由规则目录稳定确定的信息。

系统预置规则采用“代码枚举 + 数据库规则记录”的方式维护：代码枚举（建议 `TagAutoRuleCodeEnum`）登记允许的稳定 `ruleCode`、名称和所属维度；数据库记录保存来源类型、规则编码、启停状态、目标 `systemTagId` 及可供 Admin 展示的描述。新旧规则的 `raw_data` 均保持 `TagRuleRawDTO` JSON 外壳；系统规则由 `rule_type` 路由到预置策略，并以 `rule_code` 查找枚举实现，不在 `raw_data` 中重复保存另一套规则配置。应用校验系统规则编码必须存在于枚举中，未知编码不得启用。数据库中的系统规则只允许启停，不允许编辑定义或删除；自定义规则保留现有 CRUD，不为每条自定义规则新增枚举值。SQL 分为字段迁移脚本与系统规则数据脚本；系统规则数据可先登记为停用，应用侧完成规则策略、字段解析及验收后再启用。

### 5.2 命中日志与来源

规则日志记录命中、新增、撤销动作及必要的规则快照，包含可定位的 `ruleId/ruleCode`、账户、目标标签、批次和原因。标签来源需能区分自动记录与人工记录；撤销只针对自动来源记录。

### 5.3 规则计算

新旧规则的 `raw_data` 均按 `TagRuleRawDTO` 结构解析。`CUSTOM` 由通用逻辑树执行引擎计算；`SYSTEM_PRESET` 按 `rule_type` 路由到预置策略，并校验 `rule_code` 属于 `TagAutoRuleCodeEnum`。`system_rule_code` 节点用于在统一 JSON 外壳中携带系统规则路由编码；当前 Java 字段枚举和执行器尚未支持它，预置规则 SQL 入库后须保持 `Inactive`，策略实现前不得启用。目标标签 ID 不写死在枚举中，由数据库规则记录绑定当前环境的末级标签。交易聚合由批量 SQL/既有指标服务提供，不把复杂交易逻辑塞入通用逻辑树，也不逐账户 N+1 查询。

## 6. 定时任务与定向试跑

### 6.1 参数入口

沿用现有 XXL-JOB 任务，从 `XxlJobHelper.getJobParam()` 解析严格 JSON；Job 层校验后传给执行 Service，Service 不直接依赖 XXL-JOB。建议参数：

```json
{
  "mode": "PREVIEW",
  "ruleId": 123,
  "ruleType": "CUSTOM",
  "systemTagId": 456,
  "accountId": "123456"
}
```

字段说明：`ruleId` 用于定位现有规则记录；`ruleType` 筛选来源类型；`ruleCode` 用于系统预置规则；`systemTagId` 或精确 `tagName` 可定位目标标签；`accountId` 限定客户；`mode` 为 `PREVIEW` 或 `APPLY`。规则选择条件可以组合缩小范围，但互相矛盾或解析歧义时拒绝执行。标签名必须精确且唯一，并解析为活动末级标签。

### 6.2 执行安全

- 无筛选条件的正常调度默认全量 `APPLY`。
- 带规则/标签/账户筛选的手动试跑默认 `PREVIEW`，只输出预期新增、保留、撤销及原因，不写库。
- 筛选试跑若明确传 `APPLY`，必须提供 `accountId`；只影响该账户及选定互斥维度。执行时计算该维度全部有效规则，保证互斥结果正确。
- 参数错误时任务明确失败，不能忽略参数后退化为全量执行。
- 初始化游标、每日运行日期、VIP 统计期间等任务参数与试跑筛选分开校验；日志输出执行范围、模式、批次、汇总及失败原因。

## 7. Admin 与客户标签展示

- 规则列表支持按 `rule_type`、标签名、标签分类筛选，并展示规则来源与判定条件。
- 系统预置规则只允许启停；自定义规则保持当前管理行为。
- 修复新用户全量信息的客户标签字段组装，确保显示所有权限范围内的标签分类。
- 修复标签筛选项仅返回合规标签的问题；筛选项和客户列表使用同一套有权限约束的活动末级标签数据。

## 8. 实施阶段

1. **规则与数据核对：**逐条确认规则矩阵、真实标签 ID/末级状态、KYB/KYC/店铺/产品/交易数据源；核对 `tag_auto_rule` 和日志表生产结构、SQL 发布路径及现有规则数量。
2. **兼容迁移：**新增来源类型、稳定编码和所需日志动作字段；旧规则回填为 `CUSTOM`；预置规则脚本支持重复运行并校验活动末级标签。
3. **Admin 管理：**增加来源类型展示和筛选；系统预置规则只读保护；保留自定义 CRUD。
4. **计算与生命周期：**扩展规则字段及批量规则上下文；`CUSTOM` 使用通用逻辑树执行，`SYSTEM_PRESET` 按 `rule_type` 路由并通过 `rule_code` 找到预置策略；补齐末级标签校验、互斥维度计算和自动标签差异收敛；未知数据不触发撤销。
5. **定时任务：**实现初始化、每日、VIP 月度任务；增加参数筛选、PREVIEW/APPLY、安全校验、分批锁和失败重跑。
6. **客户列表修复：**修复标签展示和完整分类筛选，并保持原角色权限边界。
7. **验收与上线：**先运行预览并核对差异；执行历史初始化；观察批次、日志和错误后再启用常规定时任务。按仓库规范完成测试、编译和 `git diff --check`，不自动提交或发布。

## 9. 验收标准

- 所有新增自动标签都指向活动末级叶子标签，非叶子目标在保存、启用、初始化和执行入口均被拒绝。
- 同一客户同一互斥维度在自动来源内最多一个有效结果；规则明确失配时撤销旧自动标签，未知数据不会误删。
- 自动写入、撤销和日志可幂等重跑；人工来源标签按确认策略处理。
- 历史规则迁移后被识别为 `CUSTOM` 并继续执行；系统预置规则可识别、可启停且定义不可编辑/删除。
- 定向试跑可按规则、来源、末级标签和账户预览；筛选 `APPLY` 必须带账户 ID，且不会影响账户外数据或其他互斥维度。
- 初始化可断点续跑；每日与 VIP 月度任务独立执行；并发触发、失败批次和重试均可追踪。
- 新用户全量信息展示全部有权限标签；标签筛选覆盖全部有权限的末级标签。
- 所有待确认条件在确认前不启用，不影响已确认规则运行。
