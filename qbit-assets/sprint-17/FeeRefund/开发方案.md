# 手续费退回账单部分开发方案

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 仅在账单模块支持 `FeeRefund` 手续费退回流水，并将其作为入账金额纳入日账单、月度账单及期初期末余额计算。

**Architecture:** 复用现有三套底层交易表和账单查询链路，只在账单模块内部增加 `FeeRefund` 的查询、类型转换、汇总口径和模板展示公式。账单聚合按入账处理，金额字段、金额来源和展示字段严格沿用既有表结构及现有账单对象映射，不新增或改造金额字段；预算组账单明细的固定类型过滤改为包含 `FeeRefund`。

**Tech Stack:** Java 17、Spring Boot 3.0.2、MyBatis-Plus、MyBatis XML、PostgreSQL 15、JUnit 5。

**Spec:** `/Users/martinjiang/VsCodeProjects/martin-dev-log/qbit-assets/sprint-17/FeeRefund/手动退回功能/手动退回功能.md`

## Global Constraints

- 本期只修改账单模块，包括日账单、月度账单、账单明细、账单汇总、账单相关导出和期初期末余额计算；不实现手动退回申请、审核、执行流程。
- 不修改独立的余额交易列表、Admin 普通交易页面、通用交易查询/导出、Webhook、经营分析统计和 Interlace API。
- `FeeRefund` 的业务值固定为 `FeeRefund`，中文显示为“手续费退回”，英文显示为“Fee Refund”。
- `FeeRefund` 是入账类型；金额字段、金额来源和 `fee` 是否参与计算以既有表结构、实体字段和现有账单口径为准，本期不新增字段、不修改字段类型、不擅自将金额改存到其他字段。
- 所有新增 Java 类注释、方法注释、日志和代码注释使用中文；新增方法添加中文 Javadoc；`@author` 使用本地 git 用户名。
- 金额使用 `BigDecimal`，金额比较使用 `compareTo()`，不使用 `double` 或 `float`。
- 不修改历史流水含义，不将 `FeeRefund` 归并为 `Refund`、`Credit` 或 `Fee_Credit`。

## 验收标准

1. `FeeRefund` 在量子账户、量子卡、预算组的账单交易明细中可查、可展示、可导出。
2. `FeeRefund` 统一作为入账，金额使用各表既有金额字段和现有账单口径，不新增金额字段、不修改字段类型。
3. 日账单、月度账单的三类余额入金汇总均包含 `FeeRefund`。
4. 通过流水反推的期初、期末余额包含 `FeeRefund`。
5. 预算组不存在固定类型过滤遗漏：聚合、分页、明细、count 均支持 `FeeRefund`。
6. `Refund`、`Credit`、`Fee_Credit` 原有口径不改变。
7. 本期不引入手动退回流程、Webhook、独立余额交易列表或非账单业务改造。

## 风险与待确认项

- 需求文档提到的 `original_txn_id`、`refund_reason`、`fee_type` 是否已经落在现有交易扩展字段中，本方案账单侧暂不新增数据库字段；如账单明细确需展示，再单独扩展 VO 和查询字段。
- 当前日账单统一枚举中部分历史退款类型的方向定义存在旧口径差异，实施时只新增独立 `FEE_REFUND`，不要顺手重构历史类型。
- 月度账单现有 `ApiClientMonthFeeEnum` 主要服务客户收费计算，必须先确认真实资金账单入口，避免把手续费退回误计为应收手续费。
