# 销售佣金发薪看板前后端对接文档

## 1. 文档目标

本文档用于销售佣金发薪看板前后端联调，固定接口路径、请求参数、响应字段、页面展示映射和 mock 数据口径。

## 2. 接口总览

接口基础路径：

```text
/api/admin/sale/commission
```

| 页面区域 | 接口 | 方法 | 说明 |
|---|---|---|---|
| 我的钱包 | `/wallet` | POST | 钱包快照汇总、已回款来源聚合、发薪状态 |
| 我的绩效 | `/performance` | POST | 活动月份绩效、下一次发薪、未来发薪 |

导出接口、钱包下钻接口、绩效产品线下钻接口本期先不处理。

## 4. 通用约定

### 4.1 返回结构

后端统一使用项目现有 `Result<T>` 包装。

本文档响应示例只展示 `data` 部分，实际响应以项目统一结构为准。

### 4.2 通用请求参数

钱包和绩效主接口使用同一套 JSON 请求体。

| 参数 | 类型 | 必填 | 示例 | 说明 |
|---|---|---|---|---|
| saleId | string | 是 | `sale_001` | 查看对象销售 / AM ID |
| settlementMonth | string | 是 | `2026-04` | 结算月份，格式 `yyyy-MM` |

权限规则：

- 销售、AM 只看自己；
- 销售主管可看自己及下属销售 / AM；
- 超级管理员可看权限范围内的销售 / AM；
- 部门下拉、销售下拉使用现有接口，不在本接口新增；
- 后端必须校验当前登录用户权限，不允许通过传参越权。

### 4.3 月份规则

发薪日期固定为每月 12 号。

```text
结算月份 M
-> M+1 月 8 号生成快照
-> M+1 月 12 号发放 M 月佣金
```

示例：

```text
settlementMonth = 2026-04
-> 2026-05-08 生成 4 月快照
-> 2026-05-12 发放 4 月佣金
```

生产展示数据从 `2026-06` 开始。当前 mock 数据沿用原图 `2026-04`，只用于联调页面。

### 4.4 钱包快照规则

每月 8 号以后，我的钱包区域只查询快照数据。

快照记录：

- 返佣金额；
- 返佣组成明细；
- 当前发薪批次的有效收入、成本、GP、佣金。

快照不记录：

- 调账金额；
- 最终财务发薪金额；
- 人工发薪状态；
- 销售姓名、部门名称、客户名称等可从业务主数据关联查询的冗余字段。

发薪状态由后端根据发薪日期和当前日期推导。

接口不返回快照 ID。8 号前快照还未生成，8 号后前端也不需要依赖快照 ID 展示页面。

## 5. 枚举约定

后端返回枚举值，前端负责中文展示。

### 5.1 sourceType

| 枚举值 | 前端展示建议 | 说明 |
|---|---|---|
| real_time_processing_fee | 处理费 | 实时处理费回款 |
| billing_decline_fee | 账单/拒付 | 月账单、条件拒付等回款 |
| past_due_invoice | 逾期发票 | 历史逾期发票回款 |
| api_monthly_billing | API 月账单 | API 月账单类收入，通常进入未来发薪 |

### 5.2 pipelineType

| 枚举值 | 前端展示建议 | 说明 |
|---|---|---|
| next_payout | 下一次发薪 | 当前活动月份中已满足回款条件、预计进入最近一次发薪的数据 |
| future_payout | 未来发薪 | 当前活动月份中因回款滞后、预计进入后续发薪批次的数据 |

### 5.3 payoutStatus

| 枚举值 | 前端展示建议 |
|---|---|
| pending | 待发放 |
| paid | 已发放 |

## 6. 我的钱包接口

### 6.1 查询我的钱包

```http
POST /api/admin/sale/commission/wallet
```

#### 请求体

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| saleId | string | 是 | 查看对象销售 / AM ID |
| settlementMonth | string | 是 | 结算月份 |

```json
{
  "saleId": "sale_001",
  "settlementMonth": "2026-04"
}
```

#### 响应字段

| 字段 | 类型 | 字段含义 | 前端用途 |
|---|---|---|---|
| saleId | string | 当前查看的销售 / AM ID | 一般不展示，可用于确认当前数据对象 |
| settlementMonth | string | 当前钱包数据对应的结算月份，格式 `yyyy-MM` | 生成月份文案，例如 `2026年4月` |
| payoutStatus | string | 当前结算月份对应发薪批次的发放状态 | 发薪状态卡片展示 `待发放 / 已发放` |
| totalEffectiveRevenue | decimal | 当前钱包中，参与本次发薪的有效收入合计 | 已回款明细合计行；如页面不展示成本，可只用于校验 |
| totalCogs | decimal | 当前钱包中，参与本次发薪的成本合计 | 当前页面可不展示，后续排查 GP 口径时使用 |
| totalGp | decimal | 当前钱包中，参与本次发薪的毛利合计 | 饼图中心金额、已回款明细合计行 |
| totalCommission | decimal | 当前钱包中，按佣金规则计算出的佣金合计 | 和 `snapshotCommissionAmount` 保持一致，用于数据核对 |
| snapshotCommissionAmount | decimal | 8 号快照固化下来的实际发佣金金额 | 页面主金额：实际发佣金合计 |
| collectedItems | array | 按已回款来源聚合后的钱包明细 | 已回款毛利明细表格、回款来源饼图 |

`collectedItems` 字段说明：

| 字段 | 类型 | 字段含义 | 前端用途 |
|---|---|---|---|
| sourceType | string | 已回款来源类型枚举 | 前端映射中文名称，作为表格第一列和饼图图例 |
| effectiveRevenue | decimal | 该来源类型下参与本次发薪的有效收入 | 表格“有效收入”列 |
| gp | decimal | 该来源类型下参与本次发薪的毛利 | 表格“毛利(GP)”列；饼图按这个字段算占比 |
| commissionAmount | decimal | 该来源类型下参与本次发薪的佣金 | 表格“佣金”列；合计后等于实际发佣金合计 |

#### 响应示例

```json
{
  "saleId": "sale_001",
  "settlementMonth": "2026-04",
  "payoutStatus": "paid",
  "totalEffectiveRevenue": 50000.00,
  "totalCogs": 36600.00,
  "totalGp": 13400.00,
  "totalCommission": 1340.00,
  "snapshotCommissionAmount": 1340.00,
  "collectedItems": [
    {
      "sourceType": "real_time_processing_fee",
      "effectiveRevenue": 25000.00,
      "gp": 6800.00,
      "commissionAmount": 680.00
    },
    {
      "sourceType": "billing_decline_fee",
      "effectiveRevenue": 18000.00,
      "gp": 4900.00,
      "commissionAmount": 490.00
    },
    {
      "sourceType": "past_due_invoice",
      "effectiveRevenue": 7000.00,
      "gp": 1700.00,
      "commissionAmount": 170.00
    }
  ]
}
```

#### 前端展示映射

| 页面模块 | 接口字段 | 说明 |
|---|---|---|
| 发薪状态 | `payoutStatus` | `paid` 展示已发放，`pending` 展示待发放 |
| 回款来源月份饼图 | `collectedItems[].gp` | 前端按 GP 自算占比 |
| 已回款毛利明细 | `collectedItems` | 表格展示来源、有效收入、毛利、佣金 |
| 实际发佣金合计 | `snapshotCommissionAmount` | 当前无调账，等于 `totalCommission` |
| 上个月发放说明 | `settlementMonth` + 发薪规则 | 前端生成文案，不需要后端返回 title |

饼图计算：

```text
total = SUM(collectedItems[].gp)
ratio = item.gp / total
```

## 7. 我的绩效接口

### 7.1 查询我的绩效

```http
POST /api/admin/sale/commission/performance
```

#### 请求体

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| saleId | string | 是 | 查看对象销售 / AM ID |
| settlementMonth | string | 是 | 活动 / 结算月份 |

```json
{
  "saleId": "sale_001",
  "settlementMonth": "2026-04"
}
```

#### 响应字段

| 字段 | 类型 | 字段含义 | 前端用途 |
|---|---|---|---|
| saleId | string | 当前查看的销售 / AM ID | 一般不展示，可用于确认当前数据对象 |
| settlementMonth | string | 当前绩效活动视图对应的活动月份，格式 `yyyy-MM` | 生成活动区标题，例如 `4月1日 - 4月30日活动` |
| realTimeProcessing | decimal | 活动月份内实时处理产生的收入 | 绩效活动视图指标，可作为有效收入来源说明 |
| clientRebate | decimal | 活动月份内需要扣减的客户返利 | 绩效活动视图指标；用于解释有效收入扣减 |
| effectiveRevenue | decimal | 活动月份内用于计算 GP 的有效收入 | 绩效活动视图“有效收入” |
| cogs | decimal | 活动月份内对应成本 | 当前页面可不展示，主要用于计算 GP |
| gp | decimal | 活动月份毛利 | 绩效活动视图“毛利(GP)” |
| estimatedCommission | decimal | 活动月份按规则预估的佣金 | 绩效活动视图“预计佣金” |
| payoutPipeline | array | 当前活动月份产生的后续发薪管道 | 右侧“下一次发薪 / 未来发薪”卡片 |

`payoutPipeline` 字段说明：

| 字段 | 类型 | 字段含义 | 前端用途 |
|---|---|---|---|
| pipelineType | string | 发薪管道类型，枚举为 `next_payout` 或 `future_payout` | 决定渲染到“下一次发薪”还是“未来发薪”卡片 |
| sourceType | string | 进入该发薪管道的收入来源类型 | 前端映射中文，用于说明这笔佣金来自什么来源 |
| settlementMonth | string | 该管道最终进入发薪的结算月份 | 前端可用于生成辅助文案；一般不直接展示 |
| payoutDate | string | 该管道预计发薪日期，格式 `yyyy-MM-dd` | 生成标题，例如 `下一次发薪：5月12日` |
| effectiveRevenue | decimal | 该管道下预计进入发薪的有效收入 | 卡片底部展示 `有效收入 / GP` |
| gp | decimal | 该管道下预计进入发薪的毛利 | 卡片底部展示 `有效收入 / GP` |
| estimatedCommission | decimal | 该管道预计佣金 | 卡片右侧佣金金额 |
| status | string | 管道金额状态 | 前端可暂不展示，后续用于区分预估 / 已结算 |

#### 响应示例

```json
{
  "saleId": "sale_001",
  "settlementMonth": "2026-04",
  "realTimeProcessing": 75000.00,
  "clientRebate": 0.00,
  "effectiveRevenue": 75000.00,
  "cogs": 56500.00,
  "gp": 18500.00,
  "estimatedCommission": 1850.00,
  "payoutPipeline": [
    {
      "pipelineType": "next_payout",
      "sourceType": "real_time_processing_fee",
      "settlementMonth": "2026-04",
      "payoutDate": "2026-05-12",
      "effectiveRevenue": 60000.00,
      "gp": 12500.00,
      "estimatedCommission": 1500.00,
      "status": "estimated"
    },
    {
      "pipelineType": "future_payout",
      "sourceType": "api_monthly_billing",
      "settlementMonth": "2026-05",
      "payoutDate": "2026-06-12",
      "effectiveRevenue": 15000.00,
      "gp": 6000.00,
      "estimatedCommission": 350.00,
      "status": "estimated"
    }
  ]
}
```

#### 前端展示映射

| 页面模块 | 接口字段 | 说明 |
|---|---|---|
| 绩效活动视图 | `effectiveRevenue`、`gp`、`estimatedCommission` | 展示活动月份整体绩效 |
| 下一次发薪 | `payoutPipeline[pipelineType=next_payout]` | 前端生成标题和说明文案 |
| 未来发薪 | `payoutPipeline[pipelineType=future_payout]` | API 月账单 20 号生成后可进入该管道展示 |

注意：

```text
future_payout 只在我的绩效区域展示。
future_payout 不放在 wallet 接口里。
future_payout 不参与当前钱包快照主值计算。
```
