## 结论

这次 10→12 的分支原因可以由费率、结算历史和代码传参链共同解释：

- 2026-05-01 的交易发生在账号的 Monthly 区间。用原始交易时间计算时，旧费率服务会选择 `ApiMonthlyAsync`，把 `QuantumCardMakeCardFeeByApi` 转成 `QuantumCardMakeCardFeeByApi_Caas`，命中全局默认 **10**。
- 账号于 2026-06-02 切回 Realtime。当前重算虽然从 Java 传了原交易时间，但 QbitIssuing 的 `getMakeCardFeeV2` 没有把它传入下游 `getCardFee()`。旧 `accountFee` 回退因此拿不到交易时间，使用当前时间；按当前 Realtime 分支查询普通 `QuantumCardMakeCardFeeByApi`，命中账号级 **12**。

所以，问题不是 Java 月结任务没有传时间，而是 **QbitIssuing 的 getMakeCardFeeV2 接收了 time，却漏传给 accountFeeItemService.getCardFee**。修复这个漏传后，历史交易才能按交易发生时的 Monthly 状态计算。

## 原始交易时间核对

Java 月结任务处理钱包流水时，制卡费逻辑使用原始 `qbitCardWalletTransaction.transactionTime`：

- 制卡费计算调用 `cardProductionFee(transaction)`，并以 `transaction.getTransactionTime()` 构造费率请求。
- `getCardProductionFee(..., transactionTime)` 将该值写入请求 `param.time`。

4. QbitIssuing 的 `getMakeCardFee` 把 `time` 传给 `getMakeCardFeeV2`，但 `getMakeCardFeeV2` 调用 `getCardFee({...})` 时，入参对象里没有 `time`：[qbit-issuing.service.ts](/Users/martinjiang/WebstormProjects/qbitpay_service/src/modules/qbit-card/qbit-card/third-party/qbit-issuing/qbit-issuing.service.ts:2384)。

## 月结费率如何分支

旧费率服务先调用 `getCaasMonthFee(accountId, feeType, time)`。传入历史交易时间且当时属于 Monthly 时，返回 `ApiMonthlyAsync` 并追加 `_Caas`；见 [account-fee-v2.service.ts](/Users/martinjiang/WebstormProjects/qbitpay_service/src/modules/account-fee/account-fee-v2.service.ts:257)。

当前重算因时间缺失而使用当前时间。当前配置是 Realtime，于是 `getCaasMonthFee()` 返回 Default，不追加 `_Caas`，普通 ByApi 费率查到账号级 12。结算类型判断见 [account-fee.service.ts](/Users/martinjiang/WebstormProjects/qbitpay_service/src/modules/account-fee/account-fee.service.ts:2105)。

## 修复建议

在 QbitIssuing 的 `getMakeCardFeeV2` 中，将 `time` 加入 `getCardFee` 参数：

```ts
const fee = await this.accountFeeItemService.getCardFee({
  accountId: params.accountId,
  feeName: FeeTemplateNameEnum.QuantumCardMakeCardFee,
  amount: 0,
  country: FeeTemplateTransactionCountryEnum.all,
  bin: {
    provider: params.provider,
    firstSix: params.firstSix,
  },
  time,
  isSaveAccountFeeTransaction: false,
});
```

修复后对历史 Monthly 交易使用交易时的结算类型：2026-05-01 / 2026-05-15 交易应走 `QuantumCardMakeCardFeeByApi_Caas`，按当前提供的费率配置计算为 10。当前 Realtime 交易仍按普通 ByApi 配置计算。
