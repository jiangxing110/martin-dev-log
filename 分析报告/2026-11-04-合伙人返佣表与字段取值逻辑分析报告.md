# 合伙人返佣表与字段取值逻辑分析报告

> Updated Time: 2026-11-04 11:50:00

## 一、结论摘要

合伙人返佣由三类数据组成：毛利返佣、底价加价返佣、弹性加价返佣。

- 毛利返佣的计算输入是 `dws.dws_partner_account_profit_snapshot_p`，计算结果落在 `partner_gross_margin_commission_p`。
- 底价加价和弹性加价的实际金额来源是 `partner_commission_fee_transaction`。
- Assets 统一生成批次后，将三类结果推送到 Partner 项目的 `partner_monthly_commission` 和 `partner_monthly_commission_detail`。
- 客户与合伙人的关系通过 `account.referralCodeId -> referralCode.id -> referralCode.accountId` 建立，API 客户还需要结合 `api_account_relation`。

## 二、核心表清单

### 2.1 Assets 计算相关表

| 表 | 作用 |
|---|---|
| `dws.dws_partner_account_profit_snapshot_p` | 客户按月、按产品线的毛利快照输入 |
| `partner_gross_margin_config` | 毛利返佣配置主表 |
| `partner_gross_margin_config_detail` | 毛利阶梯明细配置 |
| `partner_gross_margin_commission_p` | 毛利返佣计算结果，按快照日期分区 |
| `partner_commission_fee_transaction` | 底价加价、弹性加价的实际交易返佣明细 |
| `partner_commission_fee_item` | 费用类型和渠道字段等辅助配置 |
| `account_fee_item` | 客户费用项目、费率类型、阶梯下限等配置 |
| `account` | 合伙人、客户账户及账户类型信息 |
| `"referralCode"` | 邀请码及合伙人客户关系 |
| `api_account_relation` | API 客户及其子账户关系 |
| `"qbitCard"` | 卡 BIN、卡组织信息 |
| `"qbit_card_transaction"` | 卡交易与卡信息关联 |

### 2.2 Partner 落库和结算相关表

| 表 | 作用 |
|---|---|
| `partner_monthly_commission` | 合伙人月度返佣主表 |
| `partner_monthly_commission_detail` | 客户、业务线、费用类型级别的返佣明细 |
| `partner_commission_transaction_bill` | 佣金账单和结算状态 |
| `partner_commission_approval_config` | 佣金审批配置 |
| `partner_commission_approval_round` | 佣金审批轮次 |
| `partner_commission_operation_log` | 佣金操作和审计日志 |

## 三、数据流转关系

```text
dws.dws_partner_account_profit_snapshot_p
        + partner_gross_margin_config
        + partner_gross_margin_config_detail
        ↓
partner_gross_margin_commission_p

partner_commission_fee_transaction
        + partner_commission_fee_item
        + account_fee_item
        + 卡交易信息
        ↓
Assets 统一返佣结果
        ↓
partner_monthly_commission
        ↓
partner_monthly_commission_detail
        ↓
佣金账单、审批、结算
```

## 四、合伙人与客户关系字段

| 字段 | 取值逻辑 |
|---|---|
| `partner_account_id` | `referralCode.accountId` |
| `customer_account_id` | 客户 `account.id` |
| `partner_type` | 合伙人 `account.type` |
| `partner_name` | 合伙人 `account.verifiedName` |
| `partner_display_id` | 合伙人 `account.displayId` |
| `customer_name` | 客户 `account.verifiedName` |
| `referral_code_id` | 客户 `account.referralCodeId` |

关系链：

```text
customer.referralCodeId = referralCode.id
referralCode.accountId = partner.id
```

## 五、毛利返佣字段

毛利结果主要来自 `dws.dws_partner_account_profit_snapshot_p`，并由毛利配置计算后写入 `partner_gross_margin_commission_p`。

| 字段 | 取值逻辑 |
|---|---|
| `snapshot_date` | 毛利快照日期，正式结算通常为次月 21 日 |
| `settlement_month` | 被结算的自然月，例如 `2026-09-21` 结算 `2026-08-01` |
| `product_line_type` | `qbit_card -> QUANTUM_ACCOUNT`；`crypto -> CRYPTO_ASSETS`；`group_account -> GLOBAL_ACCOUNT` |
| `gross_profit` | 客户在产品线和结算月内的实际毛利，可为负 |
| `commission_before_floor` | 根据毛利配置计算出的原始佣金 |
| `commission_amount` | 最终佣金，执行 `MAX(commission_before_floor, 0)` |
| `config_id` | 使用的毛利配置 ID |
| `config_effective_time` | 毛利配置生效时间 |
| `config_expiration_time` | 毛利配置失效时间 |
| `source_detail_id` | 毛利来源明细唯一标识 |
| `source_batch_no` | 本次计算或推送批次号 |

毛利规则：客户层和合伙人产品线层允许正负抵消；只有最终应付佣金执行下限 0；不同产品线之间不互相抵消。

## 六、底价加价和弹性加价字段

实际金额来源为 `partner_commission_fee_transaction`。

| 字段 | 取值逻辑 |
|---|---|
| `commission_mode` | `BasePriceMarkup` 或 `FlexibleMarkup` |
| `fee_type` | 交易记录中的 `fee_name` |
| `fee_type_name_zh` | 根据 `fee_type` 映射中文费用名称 |
| `fee_type_name_en` | 根据 `fee_type` 映射英文费用名称 |
| `rate_type` | 直接取交易记录中的 `rate_type`，通常为 `fixed` 或 `percentage` |
| `currency` | 交易费用币种，通常为 `USD` |
| `interlace_base_rate` | `rate` |
| `partner_markup_rate` | `markup_rate` |
| `customer_final_rate` | `total_rate` |
| `source_detail_id` | `partner_commission_fee_transaction.id` 转字符串 |
| `transaction_id` | 原始交易 ID，用于追溯和去重 |
| `source_id` | 业务来源 ID |
| `source_batch_no` | Assets 本次生成的推送批次号 |

金额按交易方向计算：

```text
direction = debit  ->  commission_amount = markup_fee
direction = credit ->  commission_amount = -markup_fee
```

同一交易存在 debit 和 credit 时，必须先按交易进行正负抵消，不能把两条记录都作为正向返佣。

## 七、弹性加点分成比例

`commission_share_rate` 只重点用于 `FlexibleMarkup`：

```text
commission_share_rate = partner_markup_rate / customer_final_rate
```

如果交易表已经保存了最终配置值，应优先使用交易记录中的实际配置，避免重新计算造成精度差异。底价加价模式通常不填写该字段，保持 `NULL`。

## 八、阶梯字段

阶梯信息主要从 `account_fee_item` 获取。

| 字段 | 取值逻辑 |
|---|---|
| `tier_lower_bound` | 小于等于交易金额的最大 `ladder_min_amount` |
| `tier_upper_bound` | 下一档 `ladder_min_amount` |
| `ladder_min_amount` | 当前命中的阶梯下限 |
| `ladder_max_amount` | 根据下一档下限推导，不依赖数据库维护值 |

命中规则：

```sql
amount >= ladder_min_amount
ORDER BY ladder_min_amount DESC
LIMIT 1
```

只有一档且下限为 0 时，`tier_lower_bound` 和 `tier_upper_bound` 应返回 `NULL`，避免导出成 `0-0`。

## 九、卡信息字段

量子账户业务线通过 `business_id` 关联卡信息：

```text
partner_commission_fee_transaction.business_id
        ↓
qbit_card_transaction.cardId
        ↓
qbitCard.id
```

| 字段 | 取值逻辑 |
|---|---|
| `card_bin` | `qbitCard.firstSix` |
| `card_scheme` | `qbitCard.type`，例如 `VISA` |

查不到卡信息时，可以回退到：

```text
card_bin    = partner_commission_fee_item.channel_field
card_scheme = partner_commission_fee_item.channel
```

## 十、Partner 主表和明细表

### 10.1 `partner_monthly_commission`

| 字段 | 取值逻辑 |
|---|---|
| `partner_account_id` | Assets 返回的合伙人 ID |
| `partner_type` | Assets 返回的账户类型 |
| `settlement_month` | 本次结算月 |
| `gross_profit_commission` | 毛利返佣总额 |
| `base_markup_commission` | 底价加价返佣总额 |
| `elastic_markup_commission` | 弹性加价返佣总额 |
| `total_commission` | 三种返佣金额之和 |
| `source_batch_no` | Assets 推送批次号 |
| `referred_customer_count` | 去重后的推荐客户数量 |
| `status` | 月度佣金处理状态 |

```text
total_commission
= gross_profit_commission
+ base_markup_commission
+ elastic_markup_commission
```

### 10.2 `partner_monthly_commission_detail`

明细表应保留：

- 客户和业务线信息；
- `commission_mode`、`fee_type`、费用中英文名称；
- `rate_type`、各类费率和阶梯字段；
- `commission_share_rate`；
- 卡 BIN、卡组织；
- `commission_amount`；
- `source_detail_id` 和 `source_batch_no`。

明细金额可以为负，用于保留冲正记录；月度主表最终应付金额才执行下限规则。

## 十一、容易混淆的表

| 表 | 注意事项 |
|---|---|
| `partner_gross_margin_config` | 毛利费率配置，不是返佣结果 |
| `partner_gross_margin_commission_p` | 毛利返佣计算结果，Partner 项目正式查询该表 |
| `partner_commission_fee_item` | 费用类型和辅助配置 |
| `partner_commission_fee_transaction` | 底价加价、弹性加价的实际金额来源 |
| `account_fee_transaction` | 客户普通费用交易表，不应直接替代合伙人加点交易表 |

## 十二、当前代码入口

- Assets 毛利计算：`PartnerGrossMarginCommissionJob`
- Assets 三种返佣汇总和推送：`PartnerMonthlyCommissionCalculationJob`
- Assets 查询 SQL：`PartnerGrossMarginProfitMapper.xml`
- Partner 月度主表：`partner_monthly_commission`
- Partner 月度明细表：`partner_monthly_commission_detail`
