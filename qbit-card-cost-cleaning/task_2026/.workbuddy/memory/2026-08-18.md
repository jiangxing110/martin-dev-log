## ✅ Flink JDBC 源读 PG uuid 列 ClassCastException（23:28 那次，已修）
- 报错：`java.lang.ClassCastException: java.util.UUID cannot be cast to java.lang.String`，栈在 `AbstractJdbcRowConverter.createInternalConverter` → `JdbcRowDataInputFormat.nextRecord`（**source 读取阶段**，非 sink）。
- 根因：PG 的 `uuid` 列经 JDBC 驱动返回 `java.util.UUID` 对象，Flink `jdbc` connector 的 STRING 转换器直接 `(String) getObject()` → 炸。`stringtype=unspecified` 只影响发送方向，救不了接收方向。**修法必须是 SQL 侧 CAST**。
- 生成器修复：`alias_to_cols(exprs, cols, cast_string_to_text=False)` 新增开关，对 `flink_type(c)=="STRING"` 的输出列在子查询里包 `CAST(<expr> AS text)`（varchar/text 是 no-op、uuid 正好转 String，全量开启安全）；调用处（main 的 agg_select）传 `cast_string_to_text=True`。已重生成 92 文件。
- 验证：batch/cdc 各 23 文件全覆盖；`CAST(COALESCE(SUM` 0 处（金额/时间列未误改）；01_ods_sale_am_transaction 计 2 行是因源 INSERT 自带多行注释（`NULL AS text) AS "remarks"` 合法）；JOIN/GROUP BY/id 计算仍用原始表达式不受影响。
- 经验：**Flink + PG 凡是 uuid 列且 Flink 侧声明 STRING，一律在源 subquery 里 `CAST(col AS text)`**；这是该场景的唯一正解。
