## batch 支持传入时间 + bb 式文件头（已修）
- 问题：batch 源聚合 `affected` 窗口写死 `CURRENT_DATE - INTERVAL '1 day'`（CDC 窗口），而删除函数走修复模式按 p_start/p_end 清历史区间 → 删除一段、重算只算昨天，数据缺口。
- 修复（生成器 `gen_all_jobs.py`，已重生成 23+23）：
  - 新增 `batch_window()`：batch 用 `DATE(<create_col>) >= CAST('${start_date}' AS DATE) AND <= CAST('${end_date}' AS DATE)`，与删除函数修复模式 `create_date >= p_start AND <= p_end` 严格对齐。
  - batch 删除函数调用改为 `fn_delete_<base>_cdc(false, CAST('${start_date}' AS DATE), CAST('${end_date}' AS DATE))`。sale 表作用域 CTE 同步改 `${start_date}`/`${end_date}`。
  - 新增 `header_block()`：所有 cdc/batch 文件统一加 bb 式结构化头（Author/Created/Updated/Description/作业元信息/运行参数/Notes）。
  - 运行方式：VVR 作业参数传 `start_date`、`end_date`（YYYY-MM-DD，含两端）。
- 验证：23/23 batch 含 `${start_date}`、0 `CURRENT_DATE` 泄漏（标准表）；23/23 cdc+batch 含文件头。
- 例外：`dws_sale_transfer_extend` 仍含 `CURRENT_DATE`（cdc 里 3× 也是）。属「嵌套 FROM（LATERAL unnest 子查询）」解析器限制，from_join 把原始子查询 WHERE 原样带入 → 需人工校准 SQL，与本改动无关（本来 cdc 就坏）。该表未被 [TODO] 标记命中，检测有遗漏。
