## 全量 23 表生成 + 关键 bug 修复（gen_all_jobs.py）

- 用户要求：把 transaction/extend 那套「确定性哈希主键 + 按唯一业务键精准删 + upsert」应用到原 `insert_task_job.sql` 的**全部 23 个 insert 目标表**。
- 实现：`flink_reference/gen_all_jobs.py` 解析 `../old/insert_task_job.sql`，每表产出 4 件套（DDL + 删除函数 + cdc + batch），共 92 文件。聚合逻辑留在 PG（JDBC source 跑原版子查询），Flink 只算 id + upsert。
- 重跑后「23/23 OK」的验证是**假阳性**——实际藏着会致全量脚本无法运行的 bug，逐一修掉：
  1. **PL/pgSQL 删除函数语法错**：`EXECUTE format('...')` 单引号串内含 `INTERVAL '1 day'` 与 UUID 字面量 `'0000...'`，单引号未转义 → 字符串提前终止。改为美元引号 `format($fmt$...$fmt$, ...)`，内部单引号按 PG 原文保留。
  2. **Flink `table-name` 属性值引号未转义**：JDBC source 子查询里的 `INTERVAL '1 day'`、`'0000...'` 直接嵌进 `'...' ` 属性值 → Flink DDL 解析错。改为对 `pg_subquery` 做 `.replace("'", "''")` 再嵌入（Flink 解转义后 connector 拿到正确 PG SQL）。
  3. **`find_time_cols` 改动窗口塌成 FALSE（最阴险）**：`low.endswith("createtime")` 但 `low` 只去引号没去下划线 → `tr.create_time` 不以 `createtime` 结尾 → 判定失败 → 变更窗口 = `FALSE` → CDC 跑 0 行（静默）。改为同时 `.replace('_','')`。
  4. **`parse_block` FROM 截断**：非贪婪 `.*?` 撞到嵌套 `UNION ALL` 内的第一个 `WHERE` 就停 → `from_join` 被截短 → UNION 表的 `affected` 子查询别名越界、JOIN 错位。改为括号深度感知的 `_top_level_kw` 定位主层 WHERE/GROUP BY。
  5. **ODS 无 create_date 列**：`ods_sale_fund_profits`/`ods_sale_qbit_card` 的 DWS 表没有 `create_date`，原写死 `create_date >= DATE` 路由会引用不存在的列。新增 `route_cond`（有 create_date 用 DATE，否则按 create_time/createTime 用 TIMESTAMP）+ `alias_to_cols`（让 PG 子查询输出列名对齐 DWS 列名，修掉源表达式别名错位）。
- 结果：92 文件全部正确生成；0 个未转义引号、46/46 `INTERVAL` 已转义、0 处 `WHERE FALSE`。`ods_sale_fund_profits`/`ods_sale_qbit_card` 两张 UNION+jsonb 表仍打 `[TODO]`（生成已正确，仅作复杂聚合人工复核提醒）。
- 验证手段：grep 统计未转义引号 / `INTERVAL ''1 day''` / `WHERE FALSE`；直接 import 模块复现 main 流程定位 `find_time_cols` 返回 None。
