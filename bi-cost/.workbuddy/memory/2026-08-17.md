# 2026-08-17

## bi-cost 卡片成本查询 SQL：月份维度

- 修改 `online/check/v2/query_bb_card_cost_detail_v4.sql` 与 `query_qi_card_cost_detail_v3.sql`。
- 需求：给成本汇总查询加「月份」列。
- 约定（用户纠正）：时间范围用 params.start/end_date 可跨多月（如 2026-01 ~ 2026-09，左闭右开）；**月份必须取自底层数据 `report_date`，按 `TO_CHAR(report_date,'YYYY-MM')` 分组**，不能只取 start_date（否则永远是单月）。
- 实现要点：基础聚合 CTE 加 `GROUP BY TO_CHAR(report_date,'YYYY-MM')` 并携带 `month` 列透传；QI 的 normal 与 fixed_fee 两个 CTE 各按月聚合，再用 `FULL JOIN ... ON month` 对齐（防某月只有一类费用时丢行）；最终 `ORDER BY month, sort_no`。
- 方言：PostgreSQL 风格（`DATE '...'` 字面量、`NUMERIC(20,4)`、`TO_CHAR`）。

## 输出改为透视（pivot）
- 用户要求：每个月一行，列 = month / cost / cashback（非每月三行）。
- 去掉最终 `UNION ALL`（TOTAL / Cashback Base / Cashback Income 三行），改为直接 `SELECT month, cost, cashback FROM <total CTE>`。
- 「返现」只取 Income 项（用户明确选择）：BB 用 `cashback_income`，QI 用 `channel_rebate_income`；Base 项（bb_channel_cashback_comm / channel_rebate_base）不参与。
- cost = `total_cost`（TOTAL）。两文件最终均 `ORDER BY month`。

## QI 返现拆成两列（不合计）
- 用户指出 QI 的返现由两项构成：`interchange_income`(=rebate_interchange_base_amt*rate) 与 `incentive_income`(=rebate_incentive_base_amt*rate)，原本在 `qi_total` 被加成 `channel_rebate_income` 再输出为单一 `cashback` 列。
- 改为：`qi_total` 直接输出 `interchange_income`、`incentive_income` 两列（来自 `qi_normal_detail.rebate_interchange_amount` / `rebate_incentive_amount`），最终 `SELECT month, cost, interchange_income, incentive_income`，不再有合并的 `cashback` 列。
- 与 BB 不一致：BB 仍为 `month/cost/cashback`（cashback=cashback_income，单一项）。
