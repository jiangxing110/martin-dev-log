# BB / QI 销售维度成本查询方案

## 摘要

基于现有 BB、QI 当月成本查询各新增一份销售维度版本。查询继续读取对应 v2 DWS 成本表，保留原查询的成本项、费率、返现和日期区间口径，将结果从客户维度改为按 DWS 中的 `sale_id` 汇总。可在参数中指定 `sale_id` 过滤某一销售；参数为 NULL 时查询全部销售，空字符串时查询未分配销售。

## 现状与范围

- BB 输入参考：`online/check/v2/查询_BB当月成本.sql`。
- QI 输入参考：`online/check/v2/查询_QI当月成本明细.sql`。
- 两张 DWS 表都包含销售维度字段 `sale_id`；成本数据已按销售归属生成，无需在查询时重算客户与销售的历史关系。
- 本次只新增查询 SQL，不修改现有客户维度查询，不改成本公式或费率。

## 方案

### 选择：直接按 DWS `sale_id` 汇总

BB 与 QI 分别基于现有查询复制成本核算 CTE，在范围数据中保留 `sale_id`，各成本项按 `sale_id` 分组，再输出销售 ID、成本项、计费基数、费率、金额及查询期间。空销售 ID 使用“未分配销售”显示，并作为独立分组保留。

`sale_id` 和查询日期均通过 `params` 配置；销售 ID 使用 `'替换为saleId'::varchar` 占位，替换成目标 ID 后查询该销售，设为 NULL 查询全部销售、设为空字符串查询未分配销售。日期使用左闭右开区间，默认日期与输入 SQL 一致。BB Cashback、QI Interchange / Incentive 仍作为返现收入单独列示，不并入成本总额。QI 固定成本沿用 `special_fee_type = 'CHANNEL_FIXED_FEE'` 规则。

### 考虑过的方式

1. **直接按 DWS `sale_id` 聚合（采用）**：沿用 DWS 已保存的归属和成本字段，改动小，能与现有客户维度查询逐项核对。
2. **查询时关联销售关系维表**：可以补充当前销售名称，但销售关系可能随时间变化；若未按历史有效期正确关联，可能重复或改变已计算的成本归属。本次需求只需要销售维度汇总，因此不采用。
3. **按销售和客户双重分组**：更便于下钻，但结果不再是纯销售汇总，且会扩大查询结果。本次不采用。

## 输出文件

- `online/check/v2/查询_BB当月成本_销售维度.sql`
- `online/check/v2/查询_QI当月成本明细_销售维度.sql`

## 验收口径

- 两份查询分别保留输入 SQL 的 BB / QI 成本项、费率计算和返现处理逻辑。
- 每个销售的成本按 `sale_id` 汇总；空值归入“未分配销售”。
- 可通过 `params.sale_id` 查询指定销售、全部销售或未分配销售。
- 同一日期区间内，各销售分组金额合计应能按成本项与原客户维度查询的全量数据核对。
- 不关联可能造成一对多的销售关系历史表。
