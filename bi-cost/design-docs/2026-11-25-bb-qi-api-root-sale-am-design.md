# BB、QI API 子户销售与 AM 归属

## 摘要

BB、QI 的 API 子户继承 API 根账户的销售和 AM。归属在渠道数据入库时确定，沿用已经回退的毛利视图。已有 2026 年 10 月 DWS 数据单独回填，仅更新 `sale_id`、`am_id`，保留各行及金额。

## 归属规则

| 账户 | 销售关系查找账户 | 写入规则 |
| --- | --- | --- |
| 有有效 API 根账户映射的子户 | API 根账户 | 从该根账户同一条有效销售关系取 `sale_id`、`am_id` |
| API 根账户和普通账户 | 账户本身 | 沿用该账户自身的销售关系 |

API 根账户的销售关系不存在或其中某字段为空时，对应归属留空；不取子户自己的关系补字段。渠道数据的 `account_id` 仍记录原交易或卡片所属账户。同一时刻有多条有效关系时，按生效时间及关系 ID 倒序取一条。交易和授权沿用各自事件时间，BB 活跃卡费用沿用现有作业的归属时点。

## 实施范围

1. BB 交易明细、BB 授权明细、QI 交易明细的 Batch 和 CDC 作业，在关联销售关系前先归一查找账户。每条事件只按选定账户查一次关系。
2. BB 活跃卡费用由独立作业决定归属。同样调整 Batch、CDC 及 2026 年 10 月的月度初始化脚本。
3. BB、QI 的日财务汇总继续继承 DWM 归属。渠道固定费继续继承日财务普通行的归属。
4. 毛利物化视图沿用当前版本。发布顺序为 DWM、独立费用作业、DWS；核对旧数据后再刷新毛利视图。

## 2026 年 10 月历史 DWS 回填

- 只纳入业务日为 `2026-10-01` 至 `2026-10-31`、存在有效 API 根账户映射的子户。先输出原值、目标值和候选行数，能确认根账户归属时，同时纠正错误的非空归属和缺失值。日报粒度已丢失事件时间，根账户同日存在归属切换或无法确定归属的行列为待核对。
- BB 用原业务主键定位。若目标键已存在，或多条候选会收敛成同一目标键，保留这些原行并输出冲突明细。BB 无 AM 时写空字符串，保持列约束。
- QI 用 `id + report_date` 定位。现有 `id` 由日期、账户和归属生成，按只改归属字段的要求保留 `id`。若同一日期、账户及费用类型已有相同目标归属，先列出供核对，防止重复计入。后续若要重跑覆盖该月份，需先核对历史 ID 与新作业生成的 ID。
- 历史回填只涉及归属字段。发生冲突时不合并、不删除行，生产回填和视图刷新分开执行。

## 验收

- 子户与根账户都有销售关系时，BB 和 QI 都使用根账户的销售和 AM。
- 根账户无 AM 时，不继承子户 AM。普通账户及 API 根账户仍按自身关系归属。
- 10 月回填前后，渠道表行数、成本和返现总额一致，差异只体现在销售与 AM 分组。
