# 卡渠道 API 子户销售与 AM 归属

## 当前实施范围

按最新确认，直接修改销售毛利估算物化视图。BB、QI、BZ 日财务来源的 API 子户按业务日匹配 API 根账户的同一条有效销售关系，同时用于成本和渠道返现。视图保留按销售汇总的粒度，在末尾追加 `am_id` 用于核对。现有快照按列名读取，AM 暂供视图直接查询。

为缩短物化视图构建时间，BB/QI/BZ 各自只扫描一次日报，在账户/业务日维度同时聚合成本和渠道返现；归属销售后，将成本行和返现行一次性并入总明细，避免为两个指标分支重复读取中间聚合结果。根销售及 AM 关系在聚合后的账户/日期粒度查询，AM 随渠道明细行传递，不在最终结果上逐行查询关系表。

BI 月度调账先按根账户、月份和标签聚合后，再按月初匹配销售关系。对于带时区的 `statistics_time`，同时增加对应的原列时间下界，便于数据库使用分区/索引裁剪。

## 摘要

BB、QI、BZ 的 API 子户在毛利物化视图内继承 API 根账户当天的销售和 AM，不修改上游 DWS 行。

## 归属规则

| 账户 | 销售关系查找账户 | 写入规则 |
| --- | --- | --- |
| 有有效 API 根账户映射的子户 | API 根账户 | 从该根账户同一条有效销售关系取 `sale_id`、`am_id` |
| API 根账户和普通账户 | 账户本身 | 沿用该账户自身的销售关系 |

API 根账户的销售关系不存在或其中某字段为空时，对应归属留空；不取子户自己的关系补字段。渠道数据的 `account_id` 仍记录原交易或卡片所属账户。同一时刻有多条有效关系时，按生效时间及关系 ID 倒序取一条。交易和授权沿用各自事件时间，BB 活跃卡费用沿用现有作业的归属时点。

## 实施范围

1. 本次仅修改毛利物化视图，不调整 BB/QI/BZ 上游 Batch、CDC 或 DWS/DWM。
2. BB、QI、BZ 的日财务成本与渠道返现保留各自公式，在同一次日报汇总中计算；API 子户使用根账户的当日销售归属。
3. 归属明确后分别输出成本和渠道返现明细行，合并进入视图主数据流；销售及 AM 关系只按最终输出记录核对。
4. 重建物化视图后核对 BB/QI 成本与返现合计、API 子户销售归属；既有快照须重跑对应月份。

## 历史数据处理

- 本次不回写渠道 DWS 日表。重建近六个月物化视图时，BB、QI、BZ 子户记录会按当前 API 根账户销售关系重新归属。
- 已生成的月度快照需按既有快照流程重跑对应月份，才会反映新的销售分组。

## 验收

- 子户与根账户都有销售关系时，BB、QI、BZ 都使用根账户的销售和 AM。
- 根账户无 AM 时，不继承子户 AM。普通账户及 API 根账户仍按自身关系归属。
- 每张 BB、QI、BZ 日表在视图 SQL 中只有一个事实源查询分支，成本与返现从同一聚合结果生成。
- 归属调整前后各渠道成本和返现总额一致，差异只体现在销售和 AM 分组。
