联调时请以该分支部署环境为准。

## 1. 前端要做什么

本次前端需要在客户相关页面增加“品牌名/DBA”和“官方网站”两个字段：

1. 页面增加查询输入框。
2. 列表增加品牌名/DBA、官方网站两列。
3. 新增/编辑客户时支持录入品牌名/DBA。
4. 品牌名允许多个，最多 10 个；单个品牌最多 128 个字符。
5. 品牌名去除首尾空格，并按不区分大小写去重。
6. 品牌名和官方网站同时填写时，按 AND 条件查询。

## 2. 页面改造范围

| 页面 | 接口 | 改造内容 |
| --- | --- | --- |
| CDD 审核 3.0 | GraphQL `KyCase` | 查询条件、列表字段 |
| API 客户管理-API 客户 | `POST /api/admin/apiClient/convert/api-customer/page` | 查询条件、列表字段 |
| API 客户管理-API 子客户查询 | `POST /api/admin/apiClient/convert/api-customer/sub/query/page` | 查询条件、列表字段 |
| API 客户管理-API 子客户审核 | `POST /api/admin/apiClient/convert/api-customer/sub/audit/page` | 查询条件、列表字段 |
| 新用户全量信息 | `POST /api/admin/account/list` | 查询条件、列表字段 |

## 3. 字段定义

| 字段 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| `brandNameDba` | `string[]` | 否 | 品牌名/DBA数组；无品牌时返回空数组 |
| `officialWebsite` | `string` | 否 | 官方网站 URL；列表展示字符串 |

注意：`brandNameDba` 列表返回统一为数组：

```text
["Brand One", "Brand Two"]
```

前端展示时可以直接遍历数组；如果需要标签样式，按数组元素渲染。详情编辑时不要把官网混入品牌数组。

## 7. Admin 人工维护品牌名/DBA

本次不新增独立的品牌维护页面，也不向前端暴露独立的品牌查询、新增、编辑、删除接口。

合规人员仅在 CDD API 客户审核完成后的现有客户详情/审核结果页面维护品牌名/DBA，品牌字段随现有 CDD API 审核/编辑请求一起提交。后端在原有审核保存事务内同步 `account_brand_name`，并根据提交的完整品牌数组完成新增、编辑和清空。

前端只需要改造现有 CDD API 审核/编辑请求和详情响应，不需要直接调用品牌服务接口，也不需要根据品牌记录 ID 单独删除。

### 7.1 复用的现有 CDD API 接口

主客户：

```http
POST /api/admin/apiClient/convert/api-customer/compliance/caas/edit
POST /api/admin/apiClient/convert/api-customer/compliance/baas/edit
```

子客户：

```http
POST /api/admin/apiClient/convert/api-customer/sub/compliance/caas/edit
POST /api/admin/apiClient/convert/api-customer/sub/compliance/baas/save
```

上述请求统一增加可选字段：

```json
{
  "accountId": "账户ID",
  "brandNames": ["品牌1", "品牌2"]
}
```

### 7.2 新增、编辑、清空规则

- 新增：在 `brandNames` 数组中增加品牌后，提交完整数组。
- 编辑：修改数组中的品牌后，提交修改后的完整数组。
- 删除：从数组中移除品牌后，提交剩余的完整数组。
- 清空：提交 `"brandNames": []`。
- 历史请求未传 `brandNames` 时，后端继续兼容原有 `productName` 字段；新页面保存品牌时应始终提交完整 `brandNames` 数组。
- 前端不传品牌记录 ID，不单独调用品牌新增、编辑或删除接口。
- 品牌最多 10 个，单个最多 128 个字符；服务端会 trim 并按不区分大小写去重。

### 7.3 CAAS/BAAS 详情回显

主客户详情：

```http
POST /api/admin/apiClient/convert/api-customer/compliance/caas/get
POST /api/admin/apiClient/convert/api-customer/compliance/baas/get
```

子客户详情：

```http
POST /api/admin/apiClient/convert/api-customer/sub/compliance/caas/get
POST /api/admin/apiClient/convert/api-customer/sub/compliance/baas/get
```

详情在现有 `complianceExtendVO` 中返回：

```json
{
  "productName": "历史产品名",
  "brandNames": ["品牌1", "品牌2"]
}
```

`productName` 保留用于兼容历史页面；新页面展示多品牌时使用 `brandNames`。没有品牌时返回空数组。

## 8. 客户注册流程

企业注册的 KYC 企业信息中增加可选字段：

```graphql
cddKycBusinessDetail: {
  businessName: "ABC Limited",
  brandNames: ["ABC Pay", "ABC Wallet"]
}
```

KYC 保存成功后，服务端会将品牌名以 `sourceType=KYC` 写入 `account_brand_name`。品牌名为空时不阻塞注册。

### 8.1 历史 KYC 名称说明

- 历史 KYC 的 `businessName`、`businessNameEn`、`formerName` 是企业主体名称，不是品牌名/DBA。
- 前端不要把 `businessName`、`businessNameEn`、`formerName` 自动转换为 `brandNames` 或 `brandNameDba`。
- 当前历史 KYC 数据中没有确认的标准品牌字段；历史无品牌时，品牌列表按空数组返回，列表展示 `-`。
- 新增或修改品牌只能使用本次新增的 `brandNames` 字段；品牌数据最终由后端统一写入 `account_brand_name`。

### 8.2 品牌数据全量同步范围

本次新增的品牌名需要覆盖所有写入、修改和清空入口，不能只同步注册时填写的品牌：

| 来源/场景 | 前端需要提交 | 后端同步来源 |
| --- | --- | --- |
| KYC 注册、重新提交、修改 | `cddKycBusinessDetail.brandNames` | `sourceType=KYC` |
| Admin 修改 KYC V2 | `adminUpdateKycInfo` 或 `adminUpdateBusinessKycContentByV2` 中的企业信息 `brandNames` | `sourceType=KYC` |
| CDD API 审核完成后的新增、编辑、清空 | 现有 CDD API 审核/编辑请求中的完整 `brandNames` | 由后端按 CDD API 来源同步 |
| API 客户 CAAS、BAAS | 沿用各自合规接口字段 | `sourceType=API_COMPLIANCE` |

同一账户可能同时存在多个来源的品牌。前端列表和详情应展示后端返回的全部有效品牌，不要只展示某一个来源；删除某个来源的品牌不能误删其他来源的同名或不同名品牌。

## 9. 输入校验和交互要求

- 品牌名为空字符串时不提交，或提交前过滤掉。
- 自动去除首尾空格。
- 同一账户内不允许重复品牌名，大小写不同也视为重复。
- 超过 10 个品牌时阻止提交，并提示：`品牌数量超限，保存失败`。
- 单个品牌超过 128 个字符时阻止提交，并提示：`品牌名长度不能超过128个字符`。
- 官网按普通字符串处理，建议前端校验 URL 格式，但不要擅自改写用户输入。
- 查询框点击清空后，应同时清除 `brandNameDba` 和 `officialWebsite`，重新请求列表。
- 查询条件回显时，不能把品牌名和公司法定名称混为一个字段。

## 10. 推荐组件交互

品牌名建议使用 Tag/Input 组件：

```text
[ Brand One × ] [ Brand Two × ] [请输入品牌名……]
```

回车或失焦生成一个品牌标签；提交前统一 trim、去重并校验数量和长度。

官方网站使用单行输入框：

```text
官方网站：https://example.com
```
